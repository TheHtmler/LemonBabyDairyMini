# 系统食物插画资源

本批素材使用内置 imagegen 生成，沿用用户确认的柔和手绘样张；没有使用外部图库、商标或品牌包装。

## 当前资源

- `common-atlas.png`：六列四行常见食物图集，24 个主题。
- `category-atlas.png`：首轮分类探索图集；现仅提取蛋白及蛋黄两张具体食物图。分类图已归档到 `category-study/`，不进入食物卡片。
- `upload-manifest.json`：随包具体食物缩略图清单。
- `full/plants/`、`full/proteins/`、`full/prepared/`：三组全量具体食物图、原图集、生成描述和逐编码映射。
- `full/catalog.json` 与 `full/食物配图清单.csv`：全量汇总后生成的可核对清单，包含真实图片路径、字节数、SHA-256 和版本化云路径。
- `full/upload/food-illustrations/版本/` 与 `full/食物插画-版本.zip`：按真实云路径整理的全部 JPEG 文件，可在授权后通过脚本或控制台上传；压缩包需先解压，不上传原图集。
- 小程序实际使用 `miniprogram/images/food-illustrations/*.jpg`，192×192 JPEG，单张限制 30KB。
- 生成提示词：接近实物的专业数字手绘食材图鉴插画，细腻彩铅水粉质感，自然颜色，柔和体积感；纯暖白背景，六列四行等大单元，每格仅绘制指定食物，主体居中、完整呈现、留白充足；无描边、无拟人、无文字、无商标、无分割线、非照片及非三维渲染。
- 常见食物依次为：苹果、西兰花、米饭、鸡蛋、熟鸡胸肉、牛奶；香蕉、橙子、胡萝卜、生土豆、番茄、南瓜；梨、玉米、黄瓜、菠菜、豆腐、熟面条；生猪肉、生牛肉、鱼、熟虾、吐司、大豆。
- 分类图依次为：谷物、薯类、干豆、蔬菜、菌藻、水果；坚果、畜肉、禽肉、乳制品、蛋类、水产；婴幼儿食品、小吃、速食、饮料、含酒精饮料、糖蜜；油脂、调味品、其他、餐盘、蛋白、蛋黄。

## 重新生成缩略图与检查

使用本机已有的 ImageMagick，不引入小程序运行时依赖：

```sh
npm run build:food-illustrations
npm run check:food-illustrations
npm run prepare:food-illustrations
```

构建过程只负责等分裁切、缩放和 JPEG 压缩，不重新生成图像。原始图集不进入小程序包。

## 展示优先级

用户图片优先；没有用户图片时，根据系统食物的 `sourceFoodCode` 查询具体食物图。加载中使用中性底色，已经缓存的自有照片直接使用本地文件，同图的数据刷新不重置图片。缺图、未配置云地址或下载失败时使用名称占位，不显示分类图或分类角标。食物种子和营养索引不修改。

编码映射维护在 `miniprogram/data/food-illustrations.js`，通过 `module.exports` 导出，小程序运行时不能按 Node.js 的方式直接 require JSON。全量整理脚本要求仓库全部 1,752 条食物均有具体插画，并逐项检查真实文件；粉、酱、脱水、果脯及不同部位不通过名称关键词自动套用原食材图。同外观的品牌或品种可以共用对应食物图片。

控制台列表共 13 页，前 12 页各 100 个文件、最后一页 84 个；全部 1,284 个文件 ID 与本地审核清单的文件集合一致。逐页核对记录位于 `full/console-upload-receipt.json`；该记录来自控制台列表，未下载云端文件复算摘要。既有存储规则允许读取，本次未修改权限、数据库或旧资源。

需要云端分发时，在获得生产云资源上传授权后操作：

1. 先执行 `npm run prepare:food-illustrations` 和 `npm run check:food-illustrations`，确认逐食物映射、真实图片、尺寸、体积和摘要全部一致。
2. 执行 `npm run upload:food-illustrations -- --dry-run`，只打印文件数量、字节数与版本目录，不访问云端。获得生产云上传授权后，显式传入 `--upload --env 环境ID`。
3. 上传使用项目已经安装的 `@cloudbase/node-sdk`，凭证通过本机 `CLOUDBASE_SECRET_ID`、`CLOUDBASE_SECRET_KEY` 环境变量提供；不要粘贴到聊天或写入代码。脚本不改变数据库、存储权限或旧资源。
4. 仅上传 JPEG；每张成功后保存真实文件 ID 回执，全部成功且目录一致后，才写入 `miniprogram/data/food-illustrations-cloud.js` 的 `root`。随后重新编译，完整食物配图才会按云目录加载。若当前存储规则未允许客户端读取此资源路径，需要另行确认权限处理。
5. 后续更换内容使用新的摘要版本目录，不覆盖旧版本；缓存以真实云文件 ID 区分版本。

## 下载与缓存约束

- 缩略图组件进入可见范围后才发起云图片下载，目录加载不预下载整库资源。
- 使用云文件 ID 直接下载，不为全部食物批量申请临时链接；相同图片请求合并。
- 同时最多下载 3 张；排队中的图片已离开页面或已切换食物则跳过下载。
- 独立持久化目录为 `wx.env.USER_DATA_PATH/food-image-cache-v1`，最多 20MB、2,048 文件，按最近使用淘汰；超过 2MB 的单文件只使用临时文件，不持久化。初始化用一次目录列表检查文件，避免逐文件读取阻塞首帧。
- 缓存空间不足、下载失败或缓存文件丢失时使用同食物随包图或名称占位，不影响食物选择、份量录入或营养计算。
- 云资源已上传并完成文件集合核对；未进行小程序界面验收或线上流量测量。资源体积和静态依赖检查不替代微信编译器或真机验证。
