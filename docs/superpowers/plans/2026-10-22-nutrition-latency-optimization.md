# 拍照识别等待时间优化实施计划

目标：将首页上传准备与图片采集重叠，减少重复数据库读取，并用相同图片和请求参数比较视觉模型的速度与识别结果。

依据：用户已确认实施上一轮分析中的这三项优化；当前样本选图后约 9.17 秒，其中上传准备约 1.29 秒、模型请求约 5.03 秒，识别函数其他操作约 1.81 秒。

## 约束

- 分支：`codex/nutrition-latency-optimization`；保留原有诊断、页面样式和图标等未提交改动。
- 不提交、推送、部署或变更线上默认模型；不改变图片质量、额度规则及会话结算协议。
- 按用户约定不新增、修改或扩充单元测试，仅执行语法、静态依赖与构建一致性检查。
- 不启动服务，不进行界面、模拟交互验收。模型实测仅使用用户提供的原始图片及项目配置，不使用虚构素材。
- 代码检索使用默认 code-index；修改后刷新索引。
- 模型对比的图片和原文结果仅用于用户授权的百炼调用及本地报告，控制台不得输出密钥、图片内容或个人业务编号。

## 任务与接口

- [x] 首页准备前移：独立批次保存准备 Promise、业务请求编号及不可变参数快照；正常识别仅在完整上下文匹配时接管。
  - 首页入口启动准备时不得等待网络、打开结果层或提前调用模型。
  - 单图与双图各按整批管理，绑定账号、宝宝、环境、用途、模式、图片数及分类目录。
  - 取消、模式变化、上下文变化、到期和晚到响应不能污染后续批次；原生相册显隐不误取消。
  - 不确定网络失败使用同一请求编号重试；保留普通表单和现有重试行为。
  - 保留耗时追踪，以用户真正开始识别为等待边界；准备与采集重叠阶段不能重复求和。
- [x] 后端读取精简：请求内复用服务端鉴权凭据；准备事务返回真正采用的会话；已验证会话之后并行读取模型配置和图片。
  - 默认会话访问仍鉴权，不信任客户端跳过标记；保留所有者、宝宝、过期校验。
  - 并发准备采用事务内已有会话的真实文件路径，提交失败不得返回成功。
  - 图片或配置失败仍发生在额度预留之前，保持错误优先级和失败恢复规则。
  - 共享源变更后通过现有构建脚本同步部署副本。
- [x] 同图模型对比工具：新增本地命令，复用生产请求和解析，支持不发请求的材料校验。
  - 每轮交替模型次序，使用相同图片、提示词、输出限制等参数，不自动回退。
  - 报告每次完整耗时、成功失败、词元与本地识别结果，汇总典型及慢请求数据。
  - 无样本或凭证时明确列出缺失项，不将工具准备完成表述为模型实测完成。
- [x] 实际模型比较：使用用户提供的原图及本地配置完成两模型各3次配对调用，核对结构、来源与输出一致性；营养真值和身份准确率仍未经用户或标准资料核实。
- [x] 集成检查、独立审查、修复确定问题并记录结果。

## 审查重点

1. 切换账号、宝宝或模式时，晚到准备结果不会跨业务使用。
2. 双图第一张重拍、第二张取消或批次重置时，文件顺序与预分配数量保持一致。
3. 并行准备失败不产生未处理 Promise 拒绝，不改变正常错误提示或重复创建会话。
4. 并发准备和重复识别保留幂等，额度不足、图片无效均不遗留错误状态。
5. 模型对比请求除模型名外保持相同，不把本机直连延迟等同云函数部署延迟；没有质量真值时不自动声称准确率。

## 上线与复测边界

- 后端优化需将 `recognizeNutritionLabel` 部署到实际使用环境，小程序改动需重新编译；本轮未执行这些外部变更。
- 单图在用户点击相册或快门时发起准备；双图在首张有效图片落槽后准备整批。只对首页预览接入，本地候选最多保留 5 分钟，普通表单继续原流程。
- 取消或失效可能留下未上传图片的准备草稿，沿用既有过期与清理路径，不新增自动删除任务；本轮没有核实部署侧清理调度。不会提前调用模型或占用识别次数。
- 真机复测仍需用户执行或另行明确授权；以 `recognitionStartedMs` 至 `firstUsableNutritionViewMs` 及 `prepareWait` 判断用户实际等待，不能把完整预取调用再次相加。
- 本地模型对比只衡量模型接口请求与生产解析，不包含手机上传、云函数调度、数据库或页面展示。材料和凭证准备方式见 `docs/verification/2026-10-22-nutrition-model-comparison.md`。

决策：本轮使用现有工作区的新功能分支，因先前诊断为未提交改动，避免另建工作树遗漏这些必要上下文。采用并行分工与一次集成审查；用户明确禁止新增单测、未授权界面验收，覆盖技能中的相应默认步骤。
