# 自然语言搜索版本 2 实施计划

> 执行方式：主代理使用 executing-plans 连续实施，末尾独立审查。用户本轮已授权实施设计；不在阶段之间暂停征求重复确认。

**目标：** 统一自然语言理解、真实对象识别、只读查询与结构化结果，打通“左卡摄入频次”等同义表达。

**架构：** 搜索页只发统一 search 请求。服务端把模型意图和完整确定性输入编译为能力注册表约束的版本 2 计划，再执行资料、记录及实际指标查询。真实实体、日期、单位和答案由代码确定。

**技术栈：** 原生微信小程序、CommonJS、现有 CloudBase 查询与模型接口，不添加运行时依赖。

**设计：** [完整设计](../specs/2026-10-15-natural-language-search-v2-design.md)。

## 全局约束

- 不启动微信工具，不使用游客 AppID，不请求生产 API，不部署、提交或推送。
- 不新增或修改单元测试；使用已有检查、临时离线直接调用和人工语料验收。
- 不放宽宝宝权限、功能开关、模型白名单或免费额度保护。
- 业务集合只读；临时搜索上下文和模型调用账本可以写入。
- 当前工作区有既有未提交搜索与营养功能改动，原地保留，不能从远程分支重建导致丢失。

## 审查重点

- 频次/频率同义句必须解析同一个真实药物 ID；不能用残余问句作为药名。
- 服用次数、配置频率、混合单位用量不混淆，历史资料删除后仍可查真实事件。
- 系数用有效体重和当时快照，缺值不补零，不把前七天当完整区间。
- 选择、翻页、追问均绑定账号、宝宝、计划与轮次，迟到请求不能覆盖。
- 读取失败、预算耗尽、模型不可用和无结果分别呈现，不能返回看似完整的部分总数。

接口：对象解析返回授权候选及匹配方式；上下文令牌用途签名、30 分钟过期、最多六轮；编译器返回可执行计划或一项待补选择。

- [x] 按名称/别名/可验证包含关系解析实体；统计遇重名先补问，历史药物从事件召回。

- [x] 仅完整名称或明确控件走确定性输入，其他句子进入统一模型草稿，不保留前端触发词分流。
- [x] 模型使用同一能力注册表、一次有限格式修复、既有免费策略和账本，不发送完整私有记录。
