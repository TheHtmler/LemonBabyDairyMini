# 搜索、拍照录库与 AI 设置审查修复计划

目标：落实本轮审查确认的四项修复，沿用当前功能分支并保留已有工作区改动。

实施方式：当前会话逐项实现。用户已授权四项修复；不新增或修改单元测试，不进行界面交互验收，不启动服务，不提交、推送或部署。

- [x] AI 数据库接口：共享 AI 模块统一使用 CloudBase Node SDK 的直接文档写法；管理员的 AI 操作及定时同步使用同一 SDK。读取固定模型状态时事务修复此前误写的 data 嵌套层级，不清除耗尽标记，不修改模型选择或额度查询策略。
- [x] 搜索阈值：查询协议增加待补阈值条件，保存指标、比较符、单位和计量基准；补数值时追加筛选，保留已有条件。模型指令、校验、追问与上下文共用此结构，格式缺失时要求纠正，不猜测为低于。
- [x] 自定义单位：最终手填表单允许有效的自定义记录单位；标签、参考及估算的自动换算仍限标准单位。自定义单位下最终数值按手填保存，保留原识别证据，不伪造可换算来源。
- [x] 摄入查询：普通摄入量不读取成长、历史体重和宝宝档案；系数查询加载所需日期内体重及此前最近有效记录，保留读取预算、权限限定和数据变更校验。
- [x] 验证：同步搜索和营养共享产物，执行语法、JSON、静态依赖与生成一致性检查及 git diff --check；独立复查四条调用链，记录部署范围和未执行的验收。

重点边界：已耗尽模型和旧错层级状态；高于、低于、多条件及每毫升阈值；袋、勺等自定义单位与缺失营养；历史喂奶较多、日期内无测量和此前体重缺失。
