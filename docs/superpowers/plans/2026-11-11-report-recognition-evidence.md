# 报告原行证据改造执行计划

**目标：** 血常规、血五分类CRP、血气、血氨使用原表转录、指标归属、程序校验后交付的链路。

**设计依据：** `docs/superpowers/specs/2026-11-11-report-recognition-evidence-design.md`，用户于2026-11-11确认实施。

**执行方式：** 按 writing-plans / executing-plans 技能组织实施；依据 dispatching-parallel-agents 技能，将相互独立的数值语义与名称规则交给独立代理，主代理负责云端编排和前端交接，再统一集成审阅。

## 约束

- 在当前已有功能分支继续，保留已有未提交改动，不提交、推送或部署。
- 不新增或修改单测；仅语法、静态检查与构建验证，不运行界面或模拟界面验收，不启动服务。
- 不进行真实OCR或付费调用，不发送患者样本，不新增依赖。
- 维持现有模型名单、额度、超时、并发边界与图片清理。

## 任务1：数值语义（独立）

- [x] 在 `miniprogram/utils/reportNumeric.js` 提供 `normalizeReportDetectionValue(value)` 和 `toExactReportNumber(value)`；前者返回合法结果字符串或空串，后者仅在无比较符的完整有限数值时返回数字，否则返回NaN。
- [x] 贯通 `reportNumberFormat.js`、报告模型、比较/展示/导出及图表入口，保留比较符与科学计数法，禁止阈值作为精确数值计算。
- [x] 语法检查；向主代理报告填写页、解析器需要消费的接口。

## 任务2：名称与单位约束（独立）

- [x] 修改同源 `reportRecognitionRules.js` 和必要词典；保留当前导出接口，在规则中补充目标单位。
- [x] 血常规百分比/绝对值、PCT、MCH/MCHC与血气标准/实际、离子/总钙等明确矛盾不得强制归属。
- [x] 归属语义不确定不得被别名抹去；单位不匹配返回确定的待核对原因，禁止自动换算。
- [x] 语法检查；由主代理统一生成云端副本。

## 任务3：云端转录、映射与版本（主代理）

- [x] `reportTypes.js` 定义共享协议版本及需要原行证据的类型。
- [x] 参数化现有原表适配器；来源编号由程序固定；新类型保留同指标多个来源，结构错误拒收整组。
- [x] 四类新类型逐图转录完整表格，整组按名称和单位归属，后阶段只引用原行；保留血串联、尿串联范围。
- [x] `imagePayload.js` 摘要绑定版本；云端入口交付版本、候选状态与固定类别警告。

## 任务4：前端候选和交接（主代理）

- [x] `reportRecognition.js` 检查协议版本、保留候选列表和原结果字符串，不先压成单个指标。
- [x] `reportPageMerge.js` 接受候选并保留原来源冲突；单位问题不可通过候选选择强行放行。
- [x] 识别预览展示来源、原值、单位与未回填提示；只交接可靠项目。
- [x] 填写页显示源单位并支持比较符及科学计数法，不在保存时篡改结果语义。

## 任务5：集成与审阅

- [x] 执行生成脚本同步同源规则和模型；语法检查、共享副本一致性、小程序导入检查、差异空白检查通过。
- [x] 独立审阅本次实际改动，修复影响正确性的发现；不修改单测，不提交已有工作区内容。
- [x] 刷新索引，记录验证结果与未验证范围；真实准确率、付费样本和界面验收保持待授权。

## 审阅重点

- 同页/跨图不同原值不能被评分或格式化掩盖；同一原行不能多目标复用。
- `%`、`#`、标准/实际标识和单位矛盾不能误填。
- `<0.1` 与精确值 `0.1` 不等价；比较符不能被清洗或计算吞掉。
- 新旧协议不匹配和旧幂等缓存不得绕过新链路。
- 并发失败仍等待在途调用，完整结算用量，不交付缺批次结果。
