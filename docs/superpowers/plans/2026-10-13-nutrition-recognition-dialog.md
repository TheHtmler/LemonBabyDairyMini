# 图片识别与营养回显弹窗实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 用户拍照或选图后自动接续识别、参考查询和普通食材缺项估算，在独立弹窗动态回显表单相关字段与来源，点击一次“使用结果”才回填。

**Architecture:** 沿用原生微信组件和三个既有云函数，前端流程与本地弹窗草稿分离；异步阶段逐次更新，未使用前不修改外层表单和已采用的识别会话。名称、生熟状态或参考不明确时暂停确认，再继续自动流程。

**Tech Stack:** 微信原生WXML/WXSS、CommonJS、现有CloudBase云函数和Qwen配置。

**Spec:** 本会话2026-10-13用户要求“识别+营养指标估算一次性回显、单独弹窗、动态展示、只显示本地必填/选填字段及来源”，并明确选择“点击使用结果再回填”和“先自动串联并按阶段回显”。本轮使用现有普通云函数逐阶段更新，不实施逐token流式。

## Global Constraints

- 保持当前分支、当前会话执行；不新增或修改单测，不提交、推送、部署、改生产数据或启动微信工具。
- 不自动落库；一次使用结果完成回填，外层保存继续采用已有服务端确认、版本、来源及权限规则。
- 标签/已选可信参考优先，普通食材缺项自动估算；奶粉、母乳、特医、明确品牌产品及泛称继续拒绝通用估算。
- 真实0有效，缺失不补0；不推测照片重量，不无密度换算g/ml；已有手填不被推荐值自动覆盖。
- 分类和蛋白来源由用户确认；弹窗只显示名称、表单计量基准、分类/蛋白来源、必填和选填营养、奶粉冲配量及简短来源。不展示原始JSON、token、差值、证据全文、模型内部信息。
- 取消、新表单或切宝宝丢弃迟到回显，未点击使用结果时不改变父表单及先前已采用会话。

## Review Focus

- 识别、估算中取消或切表单时不得产生父表单patch；重新识别取消后原已采用结果仍可保存。
- 已有手填和真实0不被推荐值覆盖；用户明确选择推荐或编辑字段时记录正确来源。
- 弹窗改名称、基准、制备状态或参考时旧推荐/估算作废，服务端比较版本正确更新。
- 自动查询与估算只顺序执行一次；暂停确认、失败重试不重复上传或重复图片识别。
- 弹窗在父弹窗外作为页面同级组件挂载，保持食物/奶粉父页面保存接口兼容，母乳不显示入口。
