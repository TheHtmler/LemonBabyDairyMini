# 食物多图与历史快照实施清单

**目标：** 按用户已明确的规则，保持手填营养值独立、历史编辑使用原快照、食物表单保留全部上传图片。

**实现方式：** 沿用现有小程序、云函数和食物模型；`image` 继续作为封面，新增 `images` 保存照片列表。照片沿用识别最多三张的现有边界，保存到长期食物图片目录。

**约束：** 中文文案和注释；保留当前功能分支的已有修改；不新增或运行单测、不进行界面或模拟交互验收、不提交、推送或部署。第六点只解释来源分类，本次不增加整体来源标签。

- [x] 基准份量：在识别表单及普通食物表单增加影响说明，保持用户编辑的营养数值不做联动换算。
- [x] 历史快照：调整 `meal-editor` 的取值顺序、保留原快照；`foodIntakeRecord` 不将缺少营养快照伪装成完整零值，真实零及缺项仍属于有效快照。
- [x] 多张图片：复用图片选择和上传工具；识别保存、普通新增编辑、再次打开和系统资料复制透传图片列表；表单支持预览、添加、移除和指定封面，列表仍读单张封面。
- [x] 验证：执行受影响 JS 语法、小程序静态依赖、营养共享模块一致性、模板表达式与差异检查；刷新索引并更新验证记录。

重点核对：真实零快照、目录已删除、单位或营养后来改变、图片部分上传失败后的重试、切宝宝或关闭表单后的异步返回、保存待确认时的编辑锁。
