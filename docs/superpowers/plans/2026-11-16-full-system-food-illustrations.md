# 全量系统食物插画与照片加载修正

**需求依据：** 用户反馈分类示意图不友好、自有照片会先显示分类图再切换；进一步明确选择“给全部食物补专用插画”。本计划替代首轮方案中的分类图回退。

**目标：** 仓库内 1,752 条系统食物均有具体食物插画映射；自有照片加载不经过分类图片；完整素材先在本地准备，生产云上传需按用户规则另行确认。

## 约束

- 开发使用功能分支 codex/system-food-illustrations；用户后续已明确授权提交并合并至本地 main，未授权推送远端。
- 不新增、修改或运行单元测试；只执行代码及资源静态检查，不启动服务、不进行界面验收。
- 运行时数据均为 JS 模块，不直接 require JSON。
- 具体食物的外观、部位或加工形态不同则分别配图；同外观品牌或品种可复用，不用大分类混合图片代替具体食物。
- 图片使用内置 imagegen 生成；本机 ImageMagick 负责已授权的裁切、缩放和压缩，目标 192×192 JPEG、单图不超过 30KB。

## 已定位的闪烁原因

原组件在 prepareImage 中把远程图片的 src 立即设为分类图，然后等异步下载完成才换成照片；即使已有缓存仍会显示一次错误的分类图。观察器还会在 food 对象更新时重走准备过程。

修正为按实际图片来源建立状态：有缓存立即使用缓存路径，未缓存时只显示中性底色；相同 source 更新只刷新说明信息，不重置 src 和加载状态。分类素材归档到 assets/food-illustrations/category-study，不再随包用于食物卡片。

独立代码复核未发现阻塞问题；补充修复了缓存解码失败后无法重新下载的用户可见边界问题：每个图片来源最多自动重取一次，离屏时不启动重取，再失败时回到名称占位。没有新增单元测试或进行界面验收。
