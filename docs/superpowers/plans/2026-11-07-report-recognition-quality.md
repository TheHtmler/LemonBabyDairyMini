# 报告识别清晰度与定向提取实施计划

目标：保留报告文字细节，让模型按报告类型定向提取并校验目标指标，减少无关项目误配及相同结果的无效核对。

实现方式：在当前会话顺序实施；沿用千问 OCR 单次调用、管理员配置、每图计次和现有照片加汇总表流程，不增加第二个模型调用。依据本次用户反馈及现有链路排查结果。

约束：用户本次已明确同意针对性的离线单测；不执行界面或模拟交互验收，不调用真实模型、生产接口，不提交、推送或部署；执行获授权的离线单测、语法、静态依赖和构建检查。

## 任务一：保留清晰图片

- [x] `reportTypes.js` 统一前后端图片上限为 6 MB；报告选图指定原图。
- [x] `reportRecognition.js` 上限内不压缩；超限时每次从原图按 95、90、85、80 的质量尝试，避免反复有损叠加，仍超限则明确要求分段拍摄。
- [x] 云端 `imagePreprocess.js` 同步上限；按官方 OCR 接口将图像像素预算设为 12,582,912，不再沿用默认约 8 MP 缩图阈值。

## 任务二：同源目标词典与模型定向提取

- [x] 新增 `reportRecognitionRules.js`，从报告模型和现有别名生成每类型目标名单，按完整名称或完整别名组合匹配，无法解释的前后缀不能子串吸附。
- [x] 构建脚本复制纯模型、词典和规则到报告云函数，保持提示词、服务端校验及前端解析一致。
- [x] 模型按名单提取原行、原结果和范围；血尿指标分离，相似化合物、肌酐及肌酐比等不能按部分字词归到目标指标；不以检测值是否正常来筛选。
- [x] 服务端适配器与前端结构化解析采用同源规则，记录名称匹配证据；同页重复项目优先明确完整的名称依据。

## 任务三：相同数值的信息互补

- [x] 多图结果按未舍入的原始数值判断一致性，兼容数字格式及微符号写法差异，缺失范围或单位可由同值结果补齐。
- [x] 已有范围或单位互相矛盾、检测值真实不同仍作为冲突，不按医学正常范围猜测结果；选择签名在互补合并后仍可识别。
- [x] 记录部署范围和未经真实报告验收的准确率边界。

验证：`node --test tests/report-recognition-quality.test.js tests/report-ocr-parser.test.js tests/report-number-format.test.js`（100 项通过）、`npm run build:search`、`npm run check:search`、`npm run check:nutrition`、`npm run check:miniprogram-imports`、相关 JS 语法、微信模板编译和 `git diff --check`。

重点静态审阅：精氨酸/Arg 与精氨酰琥珀酸区分；尿有机酸编号和数字前缀不被子串截取；正常空结果静默跳过；同值缺范围不产生额外核对；真正异常值保留。
