# 报告紧凑布局实施计划

> 执行方式：当前会话按 executing-plans 流程实施并独立代码审阅；用户的无单测、无界面验收、无提交约定优先于技能默认流程。

**目标：** 将已认可的紧凑原型接入真实报告，默认报告列表，完整明细与双报告同行对比。
**架构：** 复用原生页面、报告仓储和现有对比数据；抽出共享显示模型统一零值、范围与未知状态，不改变医学阈值和持久化字段。
**技术栈：** JavaScript、WXML、WXSS；不新增依赖。
**设计依据：** docs/superpowers/specs/2026-11-04-report-reference-comparison-design.md，以第二轮紧凑布局反馈及认可为准。

## 全局约束与裁定

- 使用当前分支 codex/report-analysis-focus，保留已有未提交设计文件。
- 不新增或修改单测；仅语法、静态依赖、模板结构及差异检查。
- 不启动服务，不操作或截图界面，不提交、推送或合并。
- 使用真实数据，不引入原型演示值；不实施已被否定的大摘要与宝宝插画。
- 执行记录保存在本计划，不使用要求提交或删除工作区的技能脚本。

## 重点审阅

1. 零值、空白、非数值、缺范围、零边界：状态一致，不把缺失当零或正常。
2. 同日报告、更晚对照、交换双方：对照在左、本次在右，差值本次减对照。
3. 新增编辑返回、缓存命中的聚焦：正确刷新并进入指定报告。
4. 切换宝宝或报告：过期请求不能回写旧内容。
5. 加载失败区别空数据，饮食可重试收起，无历史体重不套当前体重。

## 2026-11-04 自动预览编译错误修复

- 根因：三处 WXML 插值表达式将逻辑与写成 XML 实体，WXML 表达式编译器将实体中的分号判为非法字符。已恢复为原始逻辑运算符。
- 之前的通用 XML 结构检查会遮蔽插值内容，不能验证 WXML 表达式；后续模板验证必须单独检查表达式，具备本机 wcc 时直接执行模板编译。
- 本次验证：分析页 101 个、详情页 38 个插值表达式通过语法检查；使用微信开发者工具自带 wcc 对两页联合编译，退出码 0。
- 小程序静态依赖检查与差异检查通过；未启动预览服务或操作界面，未新增单测。
