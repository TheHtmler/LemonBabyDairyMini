# 报告分析页优化方案

日期：2026-11-04
状态：待用户确认；尚未修改产品代码。
工作分支：`codex/report-analysis-focus`

## 用户目标与本轮判断

用户指出报告分析模块的交互与显示逻辑混乱、看不到重点、用户粘度不高。

本方案由工程侧提出：让家长进入页面后，先看懂最近一次录入的报告、与上一份同类报告的变化，再决定查看明细或补充记录。通过减少阅读和操作成本改善重复使用体验；不能仅凭页面改版断言留存提升。

## 当前问题与代码依据

- `miniprogram/pages/analysis-report/index.wxml`：默认入口是按年排列的档案；对比结果前堆叠类型、日期、全部指标选择，缺少首屏重点。
- `miniprogram/utils/reportWorkbench.js`：报告列表只要异常数为零就显示“无异常”，没有区分缺参考范围、未知状态和未录入。
- 同一工具文件：对比默认 A 为最新、B 为上一份，差值按 A−B 计算，变化描述却按 A→B 叙述，阅读方向不明确。
- 对比页默认展示所有有数据的指标，摘要又逐项复述同一组变化，长报告尤为拥挤。
- 报告详情将编辑、删除放在顶部，底部再次提供删除；详情缺少继续对比的入口。
- 部分营养数值通过 `Number()` 转换，存在将空值当作零值的风险；饮食请求失败也缺少明确重试状态。

## 信息结构

沿用微信原生小程序、现有暖黄色视觉与报告仓储。本轮不新增依赖或后端集合。

页面保留两个一级入口，避免再增加一层导航：

1. **报告概览**（默认）：沿用报告类型筛选；顶部展示所选类型的最近报告，下面保留历史档案。
2. **指标对比**：默认直接给出最近两份同类报告的结果；类型与日期可修改，指标筛选按需展开。

概览内容顺序：

```text
报告概览                         指标对比
全部 / 血串联 / 尿串联 / ……

最近报告 · 类型 · 完整日期
本份已录入数量 / 超出参考范围数量 / 待补充数量
最多 3 项重点指标：名称、数值、单位、参考范围状态
[与上一份对比]                 查看完整报告

历史报告                       [添加报告]
日期 · 类型 · 状态摘要
……
```

“全部”时最近报告指当前宝宝按检测日期排序的最近一份；必须标明类型与日期，不将单份报告的结论泛化到所有类型。类型筛选同时作用于顶部摘要与档案。

## 首屏重点规则

- 优先展示这份报告中已填写且标记为偏高/偏低的指标，再补充现有配置中的关键指标，总数最多 3 项。
- 在摘要注明“展示 X 项 / 已录入 Y 项”，所有指标仍可进入详情查看。
- 不按不同单位的原始差值大小排名，不生成健康评分或病情结论。
- 无超范围项但存在未知状态时，显示“部分指标待补充参考范围”；有有效值且全部可判断时，显示“已录入指标在参考范围内”。
- 值为数值零时属于有效记录；空字符串、空白、null、undefined 和无法解析的数据不应变成零。
- 未知状态不一律认定为缺范围：若参考范围已填写但无法判定，显示“状态待核对”。
- 展示状态依据已录入数值与该报告参考范围重新派生，避免沿用清空数值后残留的旧状态；不回写历史报告。
- 只有一份同类报告时，主操作改为“添加同类报告”；无报告时提供明确的“录入第一份报告”按钮，并说明可拍照识别或手动录入。
- 没有某类报告时，保留该类型入口与添加操作，不让类型在不同使用阶段突然消失。

## 对比交互与口径

- 默认选择最近两份同类报告；从某份报告进入时，以该份为本次，优先选检测日期更早的最近一份为基准。
- 标签固定为“本次报告”和“对照报告”，展示完整日期；若用户手动选取更晚的对照报告，仍按明确的本次减对照口径计算，不再称为“较上次”。
- 同日报告仅能称为两份报告，不能宣称时间上的前后；选项附机构或可用的区分信息。
- 差值、箭头、摘要统一为“本次 − 对照”；上涨与下跌采用中性表达，颜色只用来表达相对于该份参考范围的状态。
- 顶部呈现精简摘要：可比较数量、升高/降低/相同数量、缺数值数量；不再用一段话复述所有指标。
- 默认优先展示任一份中超范围的指标，随后展示关键指标，初始最多 4 项；超过时提供“查看全部 N 项”。用户自选指标放在可展开区域中，显示已选数量。
- 自选至少保留一项，避免取消最后一项后系统偷偷全选。切换报告类型时重置为该类型默认重点。
- 一侧缺值显示“数据不足”；两侧均为有限数值时才计算差值。参考范围不一致时保留提示和各自范围。
- 现有指标不保存原报告单位，单位仅取现有配置；不猜测缺失单位，不实施跨机构单位换算。对比区域简短提示先核对原报告的单位与参考范围。
- 每份报告日期旁提供查看完整报告入口，方便核对来源。

## 饮食背景与复访路径

- 饮食背景放在指标结果之后，默认收起；明确展示两份报告各自检测前 7 天的日期范围与有效记录天数。
- 展开后可收起；加载失败显示重试，不伪装成没有记录；切换类型、报告或宝宝后，旧请求不能覆盖新状态。
- 空记录和缺体重的系数保持缺失；平均值仅纳入有效数值，不以零填补。每个系数分别显示有效天数。
- 历史系数只采用对应日期记录中有效体重，不使用宝宝当前体重冒充历史测量；现有已计算系数按其数据来源保留。
- 同一营养指标的两组柱图使用共同尺度，避免独立缩放造成相同高度代表不同数值；不推断饮食变化导致化验变化。
- 录入或编辑返回后，刷新最近报告及相关对比；处理缓存命中时的聚焦请求。
- 本轮先用“新增报告 → 看本次重点 → 一键对照 → 查看明细/补充”形成完整路径，不添加每日打卡、自动复查提醒或通知机制。

## 报告详情的衔接

- 保留编辑和复制；删除仅保留一处次要入口，沿用现有删除确认。
- 增加“与上一份对比”入口，带上当前报告、类型并切换回分析页。
- 摘要采用与概览相同的缺失/未知状态规则，避免入口与详情互相矛盾。
- 修正零值显示与单侧参考范围显示；编辑返回时刷新详情。
- 不变更报告录入字段、OCR 服务、医学判断算法、营养目标及权限模型。

## 实施边界与文件

主要修改：

- `miniprogram/pages/analysis-report/index.js`、`index.wxml`、`index.wxss`：首屏摘要、对比层级、加载/空/失败状态、明确操作入口。
- `miniprogram/utils/reportWorkbench.js`：展示摘要、选取重点、比较方向、缺失值与营养有效覆盖率。
- `miniprogram/pkg-report/report-detail/index.js`、`index.wxml`、`index.wxss`：入口衔接、展示一致性、编辑返回刷新。
- `miniprogram/models/reportRepository.js`：主报告查询失败向页面传播；仅兼容明确的集合不存在，避免网络或权限错误返回空数组。已有内容刷新失败时保留内容并提供重试。
- 可按可读性提取专用报告展示工具；公共模型修改只限上述呈现确实需要的部分，不改数据库结构。

不将独立的喂养周/月“数据分析”页纳入本轮，也不扩展 OCR、导出、分享、推送或埋点后端。
