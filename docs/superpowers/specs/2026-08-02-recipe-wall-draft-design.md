# 食谱墙草稿设计

日期：2026-08-02  
状态：已实现（待部署云函数验证）  
关联：`2026-08-01-recipe-wall-design.md`（增量，不推翻原 MVP）

## 目标

发布流程较长，允许用户先存云端草稿，稍后再补齐并上墙；草稿仅作者可见，出现在广场筛选「我发布的」。

## 决策摘要

| 项 | 结论 |
|----|------|
| 存储 | 与正式帖同一集合 `recipe_wall_posts`，用 `status` 区分 |
| 可见性 | 草稿不上广场「全部 / 我赞过的」；仅「我发布的」可见 |
| 存草稿门槛 | **标题必填**；封面 / 描述 / 用料 / 步骤可空 |
| 发布门槛 | 沿用现有完整校验 + `msgSecCheck` / `imgSecCheck` |
| 按钮位置 | **发布页底部**：`存草稿` \| `预览并发布`；预览页仍只「确认发布」 |
| 继续编辑 | 「我发布的」点草稿 → 打开发布页带 `postId` → 可再存或发布 |

## 非目标（本期不做）

- 本机自动恢复作为主能力（云端草稿已覆盖「换设备继续写」）
- 已发布帖回退为草稿
- 多版本历史 / 草稿数量上限产品化运营（可技术上允许多条草稿）
- 覆盖编辑已发布帖（仍属原设计二期）

## 数据模型变更

### `recipe_wall_posts.status`

扩展为：

| 值 | 说明 |
|----|------|
| `draft` | 草稿；仅作者在「我发布的」可见 |
| `published` | 已上墙；广场可见 |
| `taken_down` | 管理员下架；仅作者 / 管理员可见 |

其余字段与现网一致；继续要求写 `authorOpenid`（云函数显式写入）。草稿允许：

- `coverFileId` 为空
- `description` 为空字符串
- `ingredients` / `steps` 为空数组或仅占位空步骤
- `likeCount` 固定为 `0`（草稿不可被他人点赞；发布前保持 0）

可选：`publishedAt`（首次变为 `published` 时写入），便于以后排序；本期列表仍可用 `updatedAt` / `createdAt`。

## 云函数

在 `recipeWallManager` 中扩展（名称可微调，语义如下）：

| action | 说明 |
|--------|------|
| `saveDraft` | 校验标题；写入或更新 `status=draft`；**不做**内容安全检测；返回 `postId` |
| `getOwn` / `detail` 扩展 | 作者可读自己的 `draft`（及已下架）；非作者不可读草稿 |
| `publish` | 完整校验 + 安全检测；若带已有 `postId` 且属主且当前为 `draft`，则**更新并改为 `published`**；新建发布仍可无 `postId` |
| `list` + `filter=mine` | 返回作者全部状态（含 `draft`），供「我发布的」展示 |
| `list` + `all` / `liked` | 仅 `published`（不变） |
| `deleteOwn` | 作者可删草稿 / 已发布 / 已下架（归属校验用 `authorOpenid` 或 `_openid`） |
| `toggleLike` | 仅 `published` 可赞（不变） |

`saveDraft` 更新已有草稿时：覆盖表单字段与 `updatedAt`，不得把他人帖或已 `published` / `taken_down` 帖改回草稿。

图片：用户在发布页已上传到云存储的 `fileID` 可随草稿一并保存；发布时再跑 `imgSecCheck`。若发布失败因安全拒绝，草稿仍保留（或按现有策略删违规文件并提示修改——与现发布失败行为对齐，优先「保留草稿、提示改图」）。

## 前端流程

### 新建

1. FAB /「去发布」→ 发布页（无 `postId`）
2. 填标题等 → 底部：
   - **存草稿**：调 `saveDraft` → Toast → 可选返回列表并切到「我发布的」
   - **预览并发布**：完整校验通过后进预览页（沿用本地 storage 传草稿快照）；预览页「确认发布」调 `publish`（若已有 `postId` 则带上，实现「先存再发」或「未存直接发」）

未存草稿直接预览发布：`publish` 新建一条 `published` 记录（与现行为兼容）。

先存草稿再预览发布：预览确认时 `publish({ postId })`，同一条记录转正。

### 继续编辑草稿

1. 「我发布的」卡片展示状态「草稿」
2. 点击卡片 → `/pkg-recipe-wall/publish/index?id=<postId>`
3. 发布页 `onLoad` 调云函数拉取作者草稿并回填
4. 可再次「存草稿」或「预览并发布」

已发布 / 已下架：本期点击进详情（不进发布页编辑）；删除仍在「我发布的」提供。

### 列表展示

「我发布的」状态文案：

- `draft` → 草稿  
- `published` → 已发布  
- `taken_down` → 已下架  

草稿卡片：可删除；点赞按钮可隐藏或禁用（他人不可见，自己赞无意义）。

## 校验细则

### 存草稿（`saveDraft`）

- 登录 + `authorOpenid`
- `title` trim 后非空，长度上限与发布一致（≤40）
- 其余字段做轻量 normalize（非法结构丢弃或置空），不要求齐套
- 不要求宝宝展示名齐全亦可存草稿；**发布时**仍要求作者身份齐全（与现网一致）

### 发布（`publish`）

- 与现 `validatePublishPayload` + 安全检测一致
- 从草稿发布成功：`status: published`，`likeCount` 保持 0（除非已有赞——草稿期不应有赞）

## 风险与边界

| 风险 | 处理 |
|------|------|
| 草稿含未过审图片 | 仅作者可见；上墙前强制 `imgSecCheck` |
| 用户只存标题空壳 | 允许；发布时拦截 |
| 误把已发布改回草稿 | `saveDraft` 拒绝非 `draft` 目标 |
| 旧帖无 `authorOpenid` | 「我发布的」继续兼容 `_openid` 回退查询 |

## 验收标准

1. 发布页有「存草稿」「预览并发布」两个入口  
2. 仅填标题可成功存草稿，并在「我发布的」看到「草稿」  
3. 「全部 / 我赞过的」不出现草稿  
4. 打开草稿可回填并再次保存  
5. 草稿预览发布成功后变为「已发布」，广场「全部」可见  
6. 发布仍走安全检测；存草稿不走安全检测  
7. 作者可删除草稿  

## 实现顺序建议

1. 云函数：`saveDraft`、`publish` 支持 `postId`、作者读草稿、`list mine` 含 draft  
2. 发布页：双按钮、按 `id` 回填  
3. 列表「我发布的」：草稿态与点击进编辑  
4. 单测 + 部署说明（ops：无需新集合；索引仍用 `authorOpenid + createdAt`）
