# 饮食调整换算（试验）设计

日期：2026-07-27  
状态：已确认  
分支：`feature/diet-adjust-calculator`

## 背景

宝宝阶段性需要调整饮食结构（如降低奶量、增加辅食）。现有能力包括日汇总分源营养、蛋白/热量目标、配奶规划器（用奶补差额）、数据分析中的优质蛋白与供能比展示，但缺少「预选组成 → 按目标反算各品项用量 → 应用到某天」的试验工具。

## 目标

在「我的」增加试验入口「饮食调整换算」，提供分步向导：

1. 预选多种普奶、特奶与少量食物  
2. 设定蛋白或热量目标，以及奶/辅食蛋白（或热量）占比与组内份额  
3. 智能换算出各品项推荐量，允许微调  
4. 直接应用到某一天（写入全天总量型记录）

## 非目标（YAGNI / 下期）

- 数据记录页「选用模板 / 预设」入口（下期可基于同一方案模型扩展）  
- 脂肪、碳水、优质蛋白参与求解（V1 仅展示估算）  
- 按一日 N 顿均分喂奶记录  
- 挂靠配奶规划器的「反向模式」改造  

## 方案选择

采用 **独立分步向导页**（方案 1），不塞进 `milk-goal-planner-v2`。

## 入口

- 「我的」菜单新增项：名称「饮食调整换算」，描述标明试验  
- 全用户可见（非仅开发者）  
- 页面路径建议：`pkg-misc/diet-adjust-calculator/`（实现时可微调，保持分包体积可控）

## 用户流程

### ① 预选组成

- 普奶：可多选（来源：现有营养档案 / 奶粉相关配置），上限建议 5  
- 特奶：可多选，上限建议 5  
- 食物：可多选，**硬限制 1～3 种**（最多 3；若辅食侧占比 &gt; 0 则至少 1）  
- 第①步只负责选品，**不**依赖第②步的占比；占比相关校验在第②步或点击「计算」时执行  
- 点击进入第②步前的底线：至少选中 1 个品项（奶或食物任一）  

### ② 目标 + 约束 + 份额

- **目标模式（二选一）**  
  - 总蛋白（g）  
  - 总热量（kcal）  
  - 默认可按体重 × 现有系数预填（与首页目标偏好对齐），允许手改  
- **结构约束**  
  - 奶侧占比 + 辅食侧占比 = 100%（默认如 70% / 30%，可调）  
  - 蛋白模式下约束「蛋白贡献占比」；热量模式下约束「热量贡献占比」  
- **奶侧内部分层（普奶 / 特奶）**  
  - 若同时选了普奶与特奶：须设置「普奶占奶侧比例 / 特奶占奶侧比例」（默认 50% / 50%，合计 100%）  
  - 若只选普奶或只选特奶：该类占奶侧 100%，不展示该层控件  
- **组内份额**  
  - 每种已选普奶、特奶、食物各自设份额；同类合计 100%（容差 0.1%）  
  - 若某类只选 1 项，份额默认 100%  
- 计算前校验：奶侧占比 &gt; 0 则至少一种奶；辅食侧占比 &gt; 0 则至少一种食物  

### ③ 推荐量

- 展示各品项推荐量（普奶/特奶 ml 或 g，食物按库单位）  
- 允许微调数量；微调后**只重算达成值与旁注**，不再自动改回求解量  
- **应用时以微调后的数量为准**入库  
- 只读旁注：脂肪、碳水、优质蛋白估算（不参与求解）  
- 无法求解时明确错误原因（缺浓度、份额非法等）  

### ④ 应用到日期

- 选择日期（今天或未来某天；是否允许历史日：允许，由用户自担）  
- **不预查**当日是否已有记录  
- 确认弹窗文案要点：可能覆盖当天喂奶与辅食记录；确认后将删除当天奶+辅食并写入推荐量  
- 确认后执行覆盖写入（见下）  

## 换算算法

以蛋白目标为例（热量模式把「蛋白」全部换成「热量」）：

1. 全日目标值 `T`  
2. 奶侧目标 `T_milk = T × milkRatio`，辅食侧 `T_food = T × foodRatio`  
3. 将奶侧再拆到「普奶合计 / 特奶合计」（与第②步「奶侧内部分层」控件一致）：  
   - 同时有普奶+特奶：`T_normal = T_milk × normalMilkRatio`，`T_special = T_milk × specialMilkRatio`  
   - 只选一类：该类 = `T_milk`  
4. 普奶组内按各普奶份额分配 `T_normal`；特奶组、食物组同理  
5. 品项推荐量 = 分到的目标值 ÷ 该品项单位浓度（蛋白 g/单位 或 热量 kcal/单位）  
6. 浓度来源：奶用营养档案；食物用食物营养快照；缺失则该品项不可用  

输出需同时给出：推荐量列表、达成蛋白/热量、脂肪/碳水/优质蛋白估算。

## 数据写入（应用）

确认覆盖后，对目标日 `dateKey`，以**结果页当前微调后的数量**写入：

1. 先读取当日待删 id 列表（喂奶 + 辅食），再逐条删除  
2. 再按品项各写入 **1 条全天总量** 记录：  
   - 喂奶：走现有 v2 喂奶写入路径（含营养汇总字段）  
   - 辅食：走现有食物摄入写入路径  
   - 默认时间：可从 08:00 起按品项依次错开（如 +30min），避免时间轴重叠异常  
3. `DailySummaryV2Model.markDirty(babyUid, dateKey)`  
4. 小程序端无跨集合事务：采用「先删后写」；若删除已发生但写入失败，Toast 明确提示「旧记录可能已清除，请到数据记录页检查该日并手工补录」，不静默吞错  
5. 成功 Toast  

说明：确认前的弹窗**不预查**是否有旧数据；真正执行时为了删除需要列举 id（这是写入路径的必要查询，不是「有数据才允许应用」的门禁查询）。

不写入治疗、用药、尿布、喝水、睡眠等其他分类。

## 数据流

```
我的菜单
  → diet-adjust-calculator 向导
  → dietAdjustCalculator utils（纯函数求解）
  → 用户确认应用
  → FeedingRecordV2Model / FoodIntakeRecordModel（删旧写新）
  → markDirty → daily_summary_v2
```

## 错误处理

| 场景 | 行为 |
|------|------|
| 未登录 / 无宝宝 | 禁止计算与应用 |
| 份额合计 ≠ 100%（超容差） | 不允许计算 |
| 缺浓度 | 标出品项，整体不算量 |
| 推荐量 ≤ 0 | 提示调整目标或份额 |
| 应用中部分失败 | Toast 失败；提示检查该日记录 |

## 测试范围

- 求解纯函数：蛋白/热量模式、奶辅占比、多普奶多特奶份额拆分  
- 校验：份额、缺浓度、空组成  
- 应用：确认后删奶+辅食再写入；取消不写库  
- 菜单入口文案与跳转存在  

## 成功标准

- 用户可完成「多选组成 → 设目标/约束/份额 → 得到可微调推荐量 → 应用到某天」  
- 应用后该日奶/辅食被推荐量替换，日汇总可重建  
- 脂肪/碳水/优质蛋白仅展示，不阻塞求解
