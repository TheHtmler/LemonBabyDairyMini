# 食谱墙设计

日期：2026-08-01  
状态：已确认  
分支：`docs/recipe-wall-design`

## 背景

柠檬宝宝小程序当前以 MMA 喂养记录为核心。希望增加「食谱墙」，让家庭用户分享宝宝辅食 / 低蛋白 / 特医友好相关食谱，其他用户可浏览与点赞。

这是典型 UGC（用户生成内容）能力。微信要求接入内容安全机制，并在提审时声明 UGC 场景；否则容易被拒审或下架。

现有 `pkg-records/recipe-management` 等是个人配餐食谱，与「食谱墙」社交展示是两套能力，入口与命名需分开。

## 目标

- 用户可发布图文食谱，安全检测通过后立刻上墙
- 其他用户可浏览、点赞
- 列表/详情展示作者归属：`来自{宝宝昵称}{展示名}`（如「来自柠檬妈妈」）
- 管理员可下架违规内容
- 与现有云开发架构一致，复用 `msgSecCheck` / `imgSecCheck` 能力

## 非目标（YAGNI）

- 评论、收藏、关注、私信
- 用户举报入口（MVP 仅管理员下架）
- 搜索、推荐流（先按时间倒序）
- 编辑已发布内容（先删再发；编辑二期再做）
- 通用美食社区（不开放非宝宝/非低蛋白相关主题）
- 占用现有 TabBar 四席

## 方案选择

采用 **云开发原生 UGC**：

- 新集合存帖子与点赞
- 云函数统一负责发帖、安全检测、点赞、下架
- 复用现有头像安全检测模式（`checkAvatarSecurity` → `imgSecCheck`）

不采用：

- 先运营精选再开 UGC（与「用户可发」目标不符）
- 独立社区后端 / 第三方 SaaS（过重）

## 内容范围与结构

**允许主题：** 宝宝辅食、低蛋白、特医友好相关食谱。

**一条食谱字段：**

| 字段 | 必填 | 说明 |
|------|------|------|
| 封面图 | 是 | 一张 |
| 标题 | 是 | 文本 |
| 材料清单 | 是 | `[{ name, amount }]` |
| 步骤 | 是 | `[{ text, imageFileId? }]`，可多图 |
| 标签 | 否 | 如「低蛋白」「辅食」 |

## 数据模型

### `recipe_wall_posts`

| 字段 | 说明 |
|------|------|
| `_openid` | 作者 |
| `title` | 标题 |
| `coverFileId` | 封面云文件 ID |
| `ingredients` | 材料列表 |
| `steps` | 步骤列表 |
| `tags` | 可选标签 |
| `status` | `published` / `taken_down` |
| `likeCount` | 点赞数 |
| `authorDisplayName` | 发帖时快照的展示名（来自个人资料，如「妈妈」） |
| `authorAvatar` | 作者头像（可选） |
| `babyName` | 发帖时快照的宝宝昵称（如「柠檬」） |
| `babyUid` | 关联宝宝 UID（便于审计；列表展示用快照字段） |
| `createdAt` / `updatedAt` | 时间 |

作者归属文案（前端拼装，不入库整句）：

```text
来自{babyName}{authorDisplayName}
```

示例：`来自柠檬妈妈`。

未设置展示名或宝宝昵称时，不允许发帖，引导去完善资料。展示名变更不回溯历史帖。

### `recipe_wall_likes`

| 字段 | 说明 |
|------|------|
| `_openid` | 点赞用户 |
| `postId` | 帖子 ID |
| `createdAt` | 时间 |

同一用户对同一帖子仅一条点赞记录；取消赞则删除该记录并扣减计数。

### 权限原则

- 所有登录用户可读 `status=published` 帖子
- 发帖 / 点赞 / 改计数必须走云函数
- 作者可删除自己的帖子（可选但建议 MVP 提供）
- 仅管理员可将 `status` 改为 `taken_down`
- 被下架帖对普通用户不可见；作者在「我的发布」可见「已下架」

## 页面结构

入口：`我的` → `食谱墙`（分包页面，不占 Tab）。

| 页面 | 作用 |
|------|------|
| 食谱墙列表 | 卡片流：封面、标题、归属文案、赞数；可点赞；右上角「发布」 |
| 食谱详情 | 封面、标题、归属、材料、步骤、点赞 |
| 发布食谱 | 表单 + 上传；提交走安全检测 |
| 我的发布 | 自己的帖子；可删除；下架态标记 |
| 管理下架 | 仅管理员；或先用云开发控制台操作 |

建议分包根目录：`pkg-recipe-wall/`（与个人 `recipe-management` 隔离）。

## 核心流程

### 发布

1. 用户填写表单并上传图片到云存储
2. 云函数校验登录、宝宝信息、`displayName`、必填项
3. 文本内容调用 `msgSecCheck`（标题、材料、步骤文案）
4. 图片内容调用 `imgSecCheck`（封面与步骤图）
5. 任一项不通过 → 拒绝发布，删除违规已传文件，提示修改
6. 安全接口超时/失败 → 不放行上墙，提示稍后重试
7. 全部通过 → 写入 `recipe_wall_posts`（`status=published`），快照 `babyName`、`authorDisplayName`
8. 列表即时可见

### 点赞

1. 云函数按 `_openid + postId` 查是否已赞
2. 未赞：插入 like，`likeCount` 原子 +1
3. 已赞：删除 like，`likeCount` 原子 -1（不小于 0）
4. 前端可乐观更新，失败回滚

### 管理员下架

1. 校验管理员身份
2. `status` → `taken_down`
3. 列表/详情对普通用户隐藏；作者侧显示「已下架」

### 浏览

- 查询条件：`status=published`
- 排序：`createdAt` 倒序，分页
- 卡片展示：封面、标题、`来自{babyName}{authorDisplayName}`、赞数、当前用户是否已赞

## 异常处理

| 场景 | 处理 |
|------|------|
| 未登录 / 无宝宝 / 无展示名 | 引导完善资料，禁止发帖 |
| 内容安全不通过 | 明确提示；清理违规文件 |
| 安全接口失败 | 不放行；稍后重试 |
| 图片过大/格式错 | 前端压缩与校验 |
| 点赞并发 | 云函数查重 + 原子计数 |
| 帖子已下架 | 他人见「内容不可用」；作者见「已下架」 |
| 网络失败 | Toast；表单本地草稿可选 |

## 审核与合规

1. 公众平台填写 **UGC 场景声明**：文本 + 图片；机制为平台内容安全 API + 管理员下架
2. 类目与功能说明强调「宝宝辅食 / 低蛋白相关食谱分享」，避免泛美食社区表述
3. 提审版本说明建议包含：
   - 内容范围限制
   - 已接入 `msgSecCheck` / `imgSecCheck`
   - 管理员可下架
4. 隐私：发帖展示宝宝昵称与家庭成员展示名，需在产品文案中说明用途
5. MVP 无用户举报；后续若加评论/举报，需同步更新 UGC 声明

## 云函数建议（实现阶段）

| 云函数 | 职责 |
|--------|------|
| `recipeWallManager` | `publish` / `list` / `detail` / `deleteOwn` / `takeDown` / `toggleLike` |
| 或拆分 | 若单函数过大，再拆 `recipeWallPublish` / `recipeWallLike` |

安全检测逻辑可抽公共模块，对齐 `checkAvatarSecurity`。

## 成功标准

- 用户可完成：发布 → 列表看到自己的帖（含「来自柠檬妈妈」）→ 他人可点赞
- 违规文本/图片无法上墙
- 管理员可下架，下架后普通用户不可见
- 提审材料可清楚说明 UGC 与安全机制

## 后续可选（不在本次 MVP）

- 用户举报
- 收藏、评论
- 帖子编辑
- 标签筛选 / 搜索
- 人工复审队列（在自动检测之外加一层）
