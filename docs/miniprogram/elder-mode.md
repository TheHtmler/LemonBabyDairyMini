## 行为与数据

“我的 → 开启长辈模式”启用；首页顶部“退出长辈模式”回到“我的”。
`elder_mode_enabled` 是当前设备的布尔存储键，不随宝宝或家庭同步。
四个普通标签页在加载和显示时检查该键，长辈模式使用独立非标签页，
退出后恢复原生四个标签。

首页显示当前宝宝，以及记奶、记食物、记药、记喝水、记便便五个等大方形入口。
“记一笔”和“看记录”页签切换录入入口与共享列表，不重复显示底部记录总数。
首页每次显示、手动刷新和跨过午夜时读取当天记录；保存或取消打卡后返回时展示“记录已更新”。
补记往日的数据写入所选日期，因此不会出现在今天的列表里。

共享列表使用 `dailyRecordV2Service.getDailyRecordV2`，沿用 `babyUid` 查询，
不按当前录入者过滤。奶、药、水、便便、治疗、睡眠开启当日完整分页；
食物沿用现有分页。
长辈首页开启严格错误处理，模型返回失败时展示重试入口，不伪装成空态。
列表转换位于 `utils/elderRecords.js`，保留真实数量、单位、名称和备注；
奶与便便文案复用原展示工具，另展示已有治疗和睡眠记录。
喂奶卡片逐项展示奶粉名称、类型标签、粉量和水量，例如“圣元 [特奶]：15 g 90ml”，
不再重复显示总奶量和“配奶”前缀。

写入继续使用 `feeding_records_v2`、`food_intake_records`、
`medication_records`、`water_records` 和 `bowel_records`。
用药复用当前 `MedicationModel`：当前代码以 `medications` 为配置主源，
不使用技能文档中已过时的 `baby_info.medicationSettings` 描述。
记药页面复用普通首页的周期安排计算，只展示所选日期有安排的药物。
默认只突出药物名称、“今日已打卡 X 次”和每次服用对应的勾选格；
服用后点下一格“打卡”，保存成功后显示绿色勾，不必逐项填写。
已打勾的格可再次点击，取消对应那一次真实记录；取消成功后更新次数及摄入总量，
其余已打卡的格和时间保持原位，不向前挪动。仅下一空格可新增打卡。
药名右侧展示当天真实记录的累计摄入量；单位不同则分别汇总，不混加。
打卡时间始终显示为时分并可选择，保存使用界面显示的时间；已打卡格下方展示对应时分。
顶部“更多”展开日期补记、刷新、单次用量、频次和“修改本次用量”。
选择历史日期后，收起详情仍保留记录日期提示；
历史日期的次数标为“当天已打卡”。缺少有效用量或单位时不开放快捷打卡。
打卡前重新读取共享记录和配置；发现家人已更新次数或计划时刷新页面并中止本次写入。
打卡成功后留在清单，可继续记录其他药物；点“完成，返回首页”回到长辈首页。

食物记录按已有餐次编号分组，卡片标题直接显示餐名，保留各食物分量和备注；
无餐次编号的历史记录独立展示。长辈模式的餐次选择完整显示早餐、午餐、晚餐、加餐，
不使用原先固定高度的横向滚动容器。选奶粉弹窗只提供选择功能，隐藏配奶粉管理入口。

首页“看记录”的每张卡片提供“编辑 / 删除”；食物卡片提供“编辑这餐 / 删除这餐”。
奶、食物、喝水、便便、治疗和睡眠复用现有编辑页面，用药进入单次打卡编辑页。
独立的编辑、删除按钮仅位于首页“看记录”；用药打卡页通过勾选格取消单次打卡。
用药编辑页可修改日期、服用时间、实际用量和备注，保存后返回首页列表并刷新。
删除前显示日期、时间和记录内容；整餐显示餐名及食物数量，确认后更新共享列表和汇总。
记录展示编号与数据库编号分开保存，加载失败、宝宝切换或记录版本变化时不执行删除。
没有餐次编号的旧食物记录也能编辑，保存时归入独立餐次并替换原记录，保留食物备注。

普通录入保存期间及写入成功后保持提交锁，统计或上一页刷新失败不开放重复写入。
药物打卡写入或取消期间锁定按钮，完成计划次数后不能新增，但仍可取消已有打卡。
奶、食物、水、便便继续使用原表单及校验；食物和食谱选择页同步增大字号，
虚拟列表行高随之调整，防止滚动定位与实际行高不一致。
长辈食物编辑列表的首行左侧为名称、右侧为份量，下一行右侧为编辑和删除按钮。

## 验收范围

需在微信开发者工具或真机继续验收以下界面行为：

- 在“我的”开启，关闭后重新进入仍为长辈模式，退出后四个菜单恢复。
- 当前宝宝名称与录入目标一致，创建者和参与者均能看到家庭共享记录。
- 五类入口直接进入录入；取消、系统返回和保存均回到长辈首页。
- 日期时间可补记，单位清楚，缺少必需字段时不可保存，连续点击只写一笔。

- 无记录、网络失败、超过单次读取条数、重新进入和跨午夜时列表正确。
