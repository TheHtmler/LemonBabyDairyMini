# 报告识别：原图、定向提取与同值结果互补

日期：2026-11-07
分支：`codex/report-recognition-quality`

## 排查结果

1. 原先上限内图片也固定压缩到质量 80，超限后在上一次压缩结果上继续降到 20，小字、小数点及数字前缀可能受到额外损伤。
2. 模型提示词原先要求提取全部检验行，没有提供当前报告表单的目标名单；前端再按局部别名回退匹配，可能把更长或不同编号的项目归到目标指标。
3. 原先优先相信模型给出的指标编号，即使原名称与编号冲突，也可能填错字段。
4. 多图原先按结果、单位、范围整项签名比较，缺少范围、单位为空或等值数字格式差异都会造成“核对结果”；已经选定的结果补入完整信息后也可能丢失选择。

## 本次实现

- 图片上限前后端统一为 6 MB。报告选图指定原图，上限内不压缩；超限每次从原图按 95、90、85、80 尝试，仍过大则要求分段拍摄，不再反复叠加有损压缩。
- 保留 Qwen3.5 OCR、单图一次请求和管理员模型配置；将图像最大像素预算设为 12,582,912，减少原有默认约 8 MP 阈值造成的缩图。图片更清晰可能增加上传耗时及图像 Token，未做真实耗时对比。
- 模型按当前报告类型的实际录入名单，结合完整项目名、缩写、峰编号及行对应关系筛选目标。名称、检测值、单位和参考范围分字段读取，输出前检查，不按数值是否正常来删改真实异常值。
- 名单从 `ReportModel` 与既有别名生成；模型提示词、云端适配器及前端结构化解析复用同源规则。构建生成 `recognizeReportCustom/lib/report`，避免三处词典分别维护。
- 原项目名必须能由同一指标的完整名称或别名组合解释，不能只截取几个字。精氨酸/Arg 与精氨酰琥珀酸/Arg-Succ 分离；尿报告数字前缀、甲基枸橼酸(1)/(2)、3-羟基丁酸-2 等保留区分。
- 单独的肌酐行、其他化合物和比值不按局部字词吸收到目标名单；仅有模型编号而没有原项目名称证据时不盲填。模型编号与明确名称冲突时采用可验证的名称归属。
- 常见全角字符、空格、括号缩写、既有错字及已维护的别名继续支持。同页重复结果按名称证据优先级选择，不使用模型自报的置信度或“数值更正常”作为依据。
- 相同原始数值自动互补缺失范围和单位；普通小数与等值科学计数法、微符号写法及每升单位大小写差异不制造核对。互补时保留数字零边界，原选择可在信息补齐后继续识别。
- 明确不同的检测值、相互矛盾或倒置的范围、不同物理单位仍保留冲突，不自动换算或猜测。比较使用未舍入值，避免显示同为三位小数时掩盖差异；现有表单数字格式规则未扩大变更。
- 模型成功但无目标项目仍作为正常空结果，不增加失败提示；页面继续保持照片、汇总表、“继续录入”，没有新增判断流程卡片。
- 日志只增加报告类型、解析版本、图片字节数及提取/接收/过滤数量，不记录患者身份、图片或检验数值。

接口依据：[千问 OCR 官方 API 参考](https://help.aliyun.com/zh/model-studio/qwen-vl-ocr-api-reference)，支持自定义提取文本及图像像素阈值；本轮没有引入第二个模型或额外复核调用。
