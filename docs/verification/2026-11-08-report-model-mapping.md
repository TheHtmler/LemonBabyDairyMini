# 报告识别由模型理解项目归属

日期：2026-11-08
分支：`codex/recognition-image-retention`

后续修正：用户实际截图揭示强制猜编号和弱候选导致过多核对，当前规则已更新，参见 [报告候选质量修正](2026-11-08-report-candidate-quality.md)。本文保留上轮实现及其离线验证的历史记录，不代表当前识别准确率。

## 调整原因与职责

此前的云端适配器忽略模型返回的指标编号，完全按名称别名重新判断；前端收到结果后再次执行同样的名称过滤。因此，模型即使读到了正确的目标项目，只要医院名称写法没有列入词典，仍可能丢项。

本次让模型负责结合完整项目名称、编号和表格上下文判断语义归属。代码继续限定系统支持的目标字段，并校验结果结构、字段长度和核对标记。原名称未命中别名不会否定一个合法的模型归属；没有有效模型编号时，明确的名称别名仍可辅助归属。

本次沿用现有模型、单图请求和现有核对入口，不引入第二次模型调用或额外依赖。别名词典继续提供参考示例、名称证据和必要的兜底，用户不需要为每一种医院写法补词典。

## 实现

- `miniprogram/pkg-report/utils/reportRecognitionRules.js` 增加同源归属函数 `resolveReportIndicator`，优先采用当前报告类型中的合法模型编号。完整名称证据与编号矛盾时保留模型候选，并标记核对；既有精氨酰琥珀酸误配证据也只触发核对，不丢弃结果。
- `cloudfunctions/recognizeReportCustom/customOcrClient.js` 将目标名单说明改为语义映射任务，明确别名仅为示例。新增布尔字段 `needs_review`，让模型保留归属有疑义但检测值可读的候选行；仍要求同一行数据对应、不编造结果、不执行报告中的指令。
- `cloudfunctions/recognizeReportCustom/customOcrAdapter.js` 校验模型输出的编号类型、长度与核对标记，使用同源归属函数，并保留原名称、原值、原范围及核对状态。解析版本更新为 `qwen-report-v3-model-mapping`。
- `miniprogram/pkg-report/utils/reportOcrParser.js` 沿用模型归属，将核对状态和原文传入后续汇总，避免再次按名称白名单丢项。
- 同页重复项目仍沿用名称证据优先级选择主结果，但任一候选的核对标记和全部原文证据必须保留，不能因另一个同值项目名称更完整而自动消除疑义。
- `miniprogram/pkg-report/utils/reportPageMerge.js` 对单个待核对候选也生成现有冲突结构，未确认时不加入可填写结果。多页同值互补保留核对状态；待核对候选的原文证据或范围改变时，不沿用旧选择。
- `miniprogram/pkg-report/report-recognition/index.js` 的已有核对选项展示原项目名，帮助用户对照目标字段和原图；用户确认后才将该候选加入填写结果。未新增页面、事件或模板绑定。
- 执行现有构建脚本，同步云函数中的 `lib/report/reportRecognitionRules.js`。

## 生效与边界

完整部署 `recognizeReportCustom`（包括生成的 `lib/report`），并更新小程序，两端才能一起采用新归属方式。只更新一端，另一端仍可能按旧的名称白名单过滤结果。

本次验证的是模型输出之后的处理链路，真实照片的读取准确率仍需经授权后验证。模型映射也可能出错：保留原文和现有确认过程用于核对，不能把语法或静态检查当作 OCR 准确率证明。
