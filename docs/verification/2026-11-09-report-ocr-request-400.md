# 血串联报告：旧版 VL OCR 请求400

日期：2026-11-09

## 已确认的证据

- 用户反馈血串联报告识别失败，云函数日志只有 `MODEL_UNAVAILABLE` 和 HTTP 400。外层调用状态200仅表示云函数返回了错误对象，不代表模型识别成功。
- 用户确认当前报告模型属于 `qwen-vl-ocr` 或 `qwen-vl-ocr-2025-11-20`，未取得服务端原始参数错误，因此不能认定本次具体命中了哪个限制。
- 代码此前直接接受动态模型目录中的输出上限，最多发送8192；旧版 VL OCR 的4097～8192输出额度需要单独开通，模型目录中的理论上限不能证明账号具有该权限。
- 代码此前每张图片独立允许12MP，没有为整组图片分配输入预算。本会话四张原报告转换文件均为3024×4032像素；按原分辨率累加时，视觉输入规模可能超过旧版模型约30000的输入上限。
- 原失败日志没有记录模型、请求阶段或参数错误类别，无法区分转录失败与归属失败。

## 改动

- `customOcrClient.js` 按模型与图片数量计算请求限制：旧版 VL OCR 输出最多4096；整组图片使用24576视觉 Token预算，给提示词与归属原表预留空间。`qwen3.5-ocr` 使用40960视觉 Token预算，输出仍最多8192。
- 2025-11-20快照按1024像素/Token计算；稳定名称及较早的 VL OCR 按784像素/Token保守计算。每张仍最多12MP，只在整组预算更低时收紧模型的 `max_pixels`；不改写、压缩或重新保存用户图片文件。
- 四张图时，2025-11-20快照每张上限为6291456像素；稳定名称为4816896像素。多张大图的实际读取分辨率因此会下降，识别精度仍需真实回归，不承诺所有报告均无漏项。
- 血报告第二阶段继续沿用已有的旧版 VL OCR 图文请求：携带原图片与固定原行数据；两阶段共享45秒截止时间，模型输出不能覆盖原行证据，额度切换逻辑保持原样。
- 模型失败时只保留安全诊断：模型编号、`transcription`/`mapping`/`extraction`阶段、服务错误码、固定参数原因类别、图片数量、像素与输出上限。不保存服务错误原文、图片、提示词、密钥或检验数值；异常或疑似密钥形态的服务错误码替换为 `UNKNOWN`。
- 云函数 `[report-ocr-failed]` 日志输出上述安全字段。分类包含 `OUTPUT_LIMIT`、`INPUT_LIMIT`、`IMAGE_PIXELS`、`IMAGE_REQUIRED`、`IMAGE_SIZE`，无法确定时为 `INVALID_PARAMETERS`，不依据猜测填写具体原因。

## 验证与边界

- 原有两阶段测试仍使用动态模型改造前的配置样例，执行时6项均在 `CONFIG_MISSING` 处失败。已更新为合法管理员名单样例和当前累计用量契约，并补充两种旧版模型的图文归属请求验证。
