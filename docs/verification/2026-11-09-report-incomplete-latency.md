# 报告识别不完整与耗时排查

日期：2026-11-09

## 用户反馈与已确认的代码行为

- 用户反馈四张图片约7MB，识别结果不完整，怀疑超时。尚未取得本次实际等待秒数、模型结束原因或失败阶段日志，不能据文件大小认定本次超时。
- 现有模型调用共享45秒截止时间，云函数配置60秒，小程序等待70秒。本次不延长这些预算。
- “识别结果不完整，请重新拍摄或重试”来自模型结果解析器：结束原因不是 `stop` 或缺少文字结果时都会触发；真正超时另有 `MODEL_TIMEOUT`。此前没有区分输出长度截断与其他结束原因。
- 旧版 VL OCR 的血报告第二阶段原先重复发送整组图片。四张报告时，两阶段实际分别携带四张、四张图片，即使第二阶段已经有完整原表。

## 本地改动

- 第一阶段仍接收整组图片并完整转录原表；旧版模型第二阶段只保留第一张版式参考图，与完整原表文字一起做指标归属，图片数量由4＋4降为4＋1。提示词明确参考图无需再次包含原表每个项目，值仍只能从第一阶段原行读取，不能被第二阶段改写。
- 第一阶段要求紧凑 JSON，不输出缩进、说明或重复原行，降低无关格式占用输出长度的风险；未提高旧模型4096输出上限，未重新压缩用户图片。
- `finish_reason=length` 单独返回 `MODEL_OUTPUT_TRUNCATED`，提示“模型输出达到上限，报告识别结果未返回完整”；不解析或交付被截断的半份报告。
- 模型失败日志增加实际阶段、结束原因、阶段耗时、当前模型累计耗时、输入/输出 Token 数和请求参数。成功日志增加转录/归属耗时；仅保留数字和固定类别，不记录报告原文或截断内容。
- 超时记录为 `MODEL_TIMEOUT`，输出截断记录为 `OUTPUT_TRUNCATED`，其他异常不据猜测改成超时；失败时保留已消耗的模型用量。
