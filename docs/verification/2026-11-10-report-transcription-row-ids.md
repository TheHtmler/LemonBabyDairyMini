# 血报告转录重复编号修正

日期：2026-11-10

## 证据与根因

- 用户提供的日志显示 `qwen-vl-ocr` 在第2张图、共4张的 `transcription` 阶段失败，原因是 `DUPLICATE_ROW_ID`。
- 本次 `finishReason` 为 `stop`，输出1727 Token，低于4096输出上限；总函数耗时约25.4秒，因此本次不是此前的输出截断或超时。
- 逐图转录仍将模型返回的第一列直接当作唯一行编号，进入 `bloodItemsFromRows` 的Map前检查重复。同图重复编号会先触发拒绝，尚未进入跨图重新编号步骤。
- 日志能证明模型输出编号重复，不能据此断言原图印刷序号重复或检测值矛盾。转录响应已经按数组逐行保存内容，程序能够安全分配唯一编号，无需依赖模型生成的编号。

## 修改

- 在 `readBloodSourceRows` 入口完成原表结构检查，第一列作为可重复、可为空的印刷序号处理；程序按数组位置生成 `r1`、`r2` 等唯一编号，再校验临床字段和同指标冲突。
- 名称、检测值、参考范围、单位、标记五列保持原样，全部原行继续参与归属；不按印刷序号覆盖或删除行。
- 多图合并继续使用照片序号加原行位置生成 `p2r1` 等编号，保持原照片顺序，不依赖并发完成顺序。
- 提示词同步要求保留原印刷序号、缺失填null，不生成唯一编号，也不按序号合并不同原行。
- 已进入归属阶段的固定原表仍要求编号唯一；重复主键、引用不存在的行、重写原表、矛盾检测值及输出截断等校验继续有效。不在归属完成后重新编号，避免映射与证据错位。
- 解析器版本改为 `qwen-report-v10-program-row-ids`。没有增加模型调用、自动重试、时间预算或业务额度消耗方式。

## 验证

- 沿用用户已授权的离线报告解析测试范围。先用同图重复编号样例复现 `DUPLICATE_ROW_ID`，再验证重复或空序号、多种原序号与程序编号碰撞均不丢行，未收录名称可通过第二阶段语义映射。
- 新增四图编排用例：第2张图包含两个相同印刷序号，全部原行仍按程序编号进入归属，归属结果、照片来源与累计用量正确。
- 同步调整两阶段离线响应里的归属编号，使其引用程序实际发给模型的固定原表；原有归属阶段重复主键拒绝用例保持。
