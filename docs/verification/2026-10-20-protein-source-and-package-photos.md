# 蛋白来源分类与包装双向补图

日期：2026-10-20。

## 决策

- 移除按具体食品名称判断蛋白质量的名单。模型在本次图片识别中判断蛋白来源类别，程序按统一规则映射；不新增分类专用模型调用。
- 畜禽肌肉、鱼虾贝、蛋、奶、大豆及其蛋白制品映射为优质蛋白来源。谷薯、普通杂豆、蔬果、坚果种子、皮筋及胶原映射为普通蛋白来源；混合且来源不明或无法识别时留待确认。
- 大豆包括黄豆、黑大豆、青大豆和毛豆；豆腐、豆浆等按大豆来源判断。不能把红豆、绿豆等普通杂豆一并当作大豆，也不能仅凭“肉味”“奶味”或包装图案推断来源。
- 保存方式、生熟状态、蛋白质克数不决定来源分类。前端标记为 AI 建议；用户明确修改后保留用户选择。特殊营养配方仍需明确身份和人工确认。
- 此字段用于本应用的蛋白来源分类，不代表产品的实测氨基酸评分或整体健康程度。

## 包装识别

- 新增 `packageEvidence.identity` 与 `packageEvidence.nutrition`，保存识别图片中的商品身份文字、营养表标题或表头依据；校验图片序号和非空文字。
- 只有营养表、缺商品名称时允许保留有效标签观察结果，名称留空，不编造通用商品名称。实物模式仍要求有效名称，多产品冲突仍需要重新核对。
- 结果浮窗按缺项提示：缺身份补正面，缺必要营养或表头基准补营养表，两者均缺提示补充包装图片。一面含有完整信息就不要求第二面。
- 已识别读数与补图提示同时保留；真实零值有效，基准待确认的标签读数不会被隐藏。普通食物实物的预览展示沿用原流程。
- 缺身份时先停止参考查询和保存，用户补图或手动确认名称后继续；保存端也拦截空身份。
- 最多三张图片，补图时原图和新增图共同识别。沿用占一次识别次数的提示和旧草稿恢复。图片满时仍提供重拍及手动确认入口。
- 包装正面不能作为营养数值的依据；本次没有新增联网商品数据库，不凭商品名称估算包装标签。

## 主要文件

- `packages/nutrition-recognition-core/classification.js`：来源类别及统一质量映射。
- `packages/nutrition-recognition-core/normalize.js`：包装证据校验、无商品名称的营养表结果保留。
- `cloudfunctions/recognizeNutritionLabel/modelClient.js`：分类与双面信息的提取约定。
- `cloudfunctions/confirmNutritionRecognition/index.js`：保存前的身份检查。
- `miniprogram/pkg-milk/components/nutrition-recognition/`：识别草稿、补图状态、短提示及主操作。

## 依据

- [国家卫健委：合理膳食健康教育核心信息](https://www.nhc.gov.cn/xcs/cbcl/201706/d7d8ff3889be445b8bfb86a5efea952f.shtml)：鱼、禽、蛋、瘦肉、奶和大豆是优质蛋白质来源。
- [国家卫健委：2024 年 11 月 14 日新闻发布会文字实录](https://www.nhc.gov.cn/xcs/c100122/202411/f63a9692d1294dd19c595dce73404417.shtml)：区分大豆和普通杂豆，大豆中的黄豆、黑豆、青豆与红豆、绿豆等不能互相替代。

## 验证与发布

本轮仅执行代码层面的验证，不新增或修改单元测试，不启动服务、不进行界面或模拟交互验收，不调用生产识别接口。

- `npm run build:nutrition`、`npm run check:nutrition` 通过，共享模块与三个云函数及小程序产物一致。
- `npm run check:search` 通过，包含 65 个页面/组件、368 个文件、403 处静态引用的检查。
- 修改的 JavaScript 语法、模板中的 95 处事件绑定、320 处表达式、标签闭合及 `git diff --check` 均通过。
- 代码静态复核覆盖：只有正面、只有营养表、信息齐全、图片满三张、真实零值、标签基准缺失及手动确认身份。未使用真实照片验证模型是否准确返回来源类别和包装依据，不能将静态检查视为识别准确率验证。

发布时需要重新编译小程序，并更新三个携带共享营养模块的云函数：`recognizeNutritionLabel`、`lookupNutritionReference`、`confirmNutritionRecognition`。本地修改未部署。
