# 血报告真实测速与重复调用优化

日期：2026-11-10

## 目标与授权

- 用户明确目标是缩短实际识别耗时，而非扩大执行超时时间。本轮没有修改时间预算或云端配置。
- 用户重新明确允许一次真实测速，范围为原四张血报告、当前 `qwen-vl-ocr`，只记录耗时、数量和用量，不保存报告记录。
- 本机脚本为 `/private/tmp/lemon-report-ocr-check/benchmark-speed.js`，默认仅检查本机输入，显式 `--execute` 才发送图片。已在取得该次明确授权后执行一次，没有自动复测或追加付费调用。

## 测速结果

- 运行版本：`qwen-report-v12-source-reuse`。模型链路总耗时29929毫秒，四张图并行转录。
- 第1张29925毫秒、输出1497 Token；第2张26486毫秒、输出1727 Token；第3张28109毫秒、输出1760 Token；第4张26824毫秒、输出1531 Token。
- 四次响应的结束原因均为 `stop`，每次输入12302 Token，总输入49208、总输出6515 Token。第3张因 `ROW_SHAPE_INVALID` 被拒绝，其他三张通过本地结构检查。
- 实际执行了四次转录请求，没有进入归属阶段。因此29.9秒是本次失败链路耗时，不能当作完整成功报告的识别耗时，也不能据此声称已比上一版提速多少。
- 输入是此前转换的四张JPEG，共14832293字节；本机直连只测模型链路，不包含手机上传、云下载、权限和业务额度处理，不能等同于手机端到端耗时。
- 未输出或保存模型正文，故不能确认第3张具体返回了几列或缺了哪个字段；现有证据只能确认它不满足旧协议的六列位置数组约定。

## 已完成的本地优化

- 保留上一轮三张并行上传、四图同轮转录、紧凑名称归属输入及低像素兼容参考图。
- 备用模型切换时，在同一次请求的内存中复用已验证原表；兼容的逐图批次只补失败照片，成功空页也复用；归属失败后切换模型只重做归属，避免重新识别全组。
- 该复用只优化备用模型路径，正常成功路径仍为四次转录加一次归属。不会将它描述为正常路径已经减少到四次模型调用。
- 缓存与当前图片组绑定，不跨请求复用、不新增数据库记录；复用内容仍按照片顺序固定原行，原值、矛盾检测值和错误行引用校验继续有效。
- 增加安全的 `[report-ocr-call]` 开始及结束日志，记录模型、阶段、批次、耗时和Token用量，不记录原表、提示词、图片、密钥或服务原始响应。

## 测速失败后的结构调整

- 模型转录协议从依赖列数的位置数组改为紧凑对象：`n`原名、`v`原值、`r`原参考范围、`u`原单位、`f`原标记；`n`和`v`必须存在，无法读取时为null，其余字段可缺省。
- 不再要求模型输出不参与匹配的印刷序号；程序按原行顺序生成唯一编号，按字段名固定原始临床数据。内部原行证据与归属选择仍隔离，不根据值或范围猜项目，不把缺省字段从邻行补齐。
- 不保留旧转录协议的兼容分支。缺失必填字段、错误字段类型、截断JSON、矛盾读数等错误仍拒绝。
- 当前本地版本为 `qwen-report-v13-named-source-rows`。该版本只完成离线验证，未在本次授权外继续真实复测，不能声称第3张真实图片已成功识别。

## 验证与结论

- 新增备用模型复用用例，先复现了整组重新转录，再验证只补失败照片、成功空页复用、来源稳定和用量累计；转录对象协议用例先复现旧解析拒绝，再验证可缺字段、固定原值、语义归属与错误引用检查。
- 十三个相关离线测试文件共208项通过；`npm run check:search`、相关JavaScript语法检查及 `git diff --check` 通过，代码索引已刷新。
- 未进行界面或模拟页面交互验收，未部署、提交或推送。生效需完整部署 `recognizeReportCustom`（含 `lib`）并更新包含并行上传的小程序代码。
- 目前真实数据说明当前模型单张转录约26至30秒是主要耗时，尚无成功完整链路的实测结果。后续降低像素预算或更换模型均需要比较速度与小字、小数点、错行和漏项情况，不能仅靠离线测试证明准确率及速度兼得；再次付费调用需另获授权。
