# 识别图片留存与发布记录

## 留存规则

- 食物识别保存一张封面，沿用现有图片预处理；不改变参与识别的图片。
- 包装识别保存选定封面与营养表依据，优先采用模型的图片索引；用户移除的图片不会重新保留。相同图片去重，最多两张。
- 报告识别默认不长期保存图片；用户勾选“保存原报告”后，保存表单时才上传独立附件，最多6张。包括本次仍在识别或失败的照片，保留原始拍摄内容，供之后核对。
- 报告附件使用 `report_originals/<babyUid>/<openid>/<随机32位>.jpg`，不复用 `custom_ocr_temp/`。数据库只记录文件ID，不保存临时下载地址。
- 编辑报告保留现有附件，继续识别可以追加新附件；超过6张时明确提示不追加，不影响已识别的指标。
- 详情通过云函数验证宝宝成员关系和报告归属后取得原图链接。分享页面不直接携带原图链接。
- 有附件的报告删除由云函数重新读取报告，只删除当前环境、当前宝宝目录、报告已引用的附件；每项删除成功才删除记录。部分失败保留记录供重试；已成功删除的附件可能暂时无法查看。

## 临时图片的三层清理

1. 报告前端原有 `finally` 尽力删除上传图片。
2. 报告云函数新增 `finally` 删除已经校验并开始处理的临时文件，覆盖小程序中途退出而云函数仍正常执行完成的情况。
3. 发布时合并 `config/recognition-image-lifecycle.json` 中的两条 COS 生命周期规则，处理上传后未发起识别、云函数被终止或删除失败的残留。

报告临时目录配置为1天；营养识别草稿有效期24小时，临时目录配置为2天，避免临近有效期仍可确认的草稿提前丢图。生命周期按对象最后修改时间计算并异步执行，不承诺精确24/48小时删除。

生命周期仅覆盖 `custom_ocr_temp/`、`nutrition_recognition/`，不包含 `food_images/`、`report_originals/` 或任何其他资料目录。原有营养草稿清理脚本仍可用于清理过期数据库记录，不要求为了删除临时图执行该脚本。

## 发布步骤

1. 先导出现有云存储权限和生命周期配置，合并规则，不能用本文件直接覆盖全桶现有规则；确认桶及云环境对应正确。生命周期规则也会覆盖临时目录中已经过期的历史文件。
2. 确认 `report_originals/` 对匿名用户及无关用户不可读、不可写；文件上传者可写，宝宝其他成员通过已鉴权的云函数查看。不要保留会覆盖此目录的公开读规则。
3. 云存储为全桶表达式权限时，需要在现有规则中合并公开资料目录白名单及创建者权限。参考官方创建者条件 `resource.openid == auth.openid || resource.openid == auth.uid`，不能简单将全桶改为公开读。当前线上规则未知，因此本次不提供会覆盖其他业务权限的全桶规则。
4. 完整部署 `recognizeReportCustom`（包含 `originalImages.js`），先保留 `REPORT_ORIGINALS_ENABLED` 关闭。确认私有目录及访问权限后，显式设 `REPORT_ORIGINALS_ENABLED=true`，再发布小程序。
5. 开关关闭或旧云函数未部署时不显示“保存原报告”；指标识别和手动录入照常工作。关闭开关只停止新增附件，不阻断已有附件查看和删除。

本次没有部署、修改线上权限或执行线上删除。发布后的真实权限与生命周期行为仍需在获得验收授权后验证。

## 保存失败边界

- 原图只在点击保存时上传，不在识别确认时额外上传。上传失败回收本次已完成上传的文件；只在表单内缓存成功附件ID，重试复用，避免重复上传。
- 数据库写入结果不确定时不删除已上传附件，避免网络超时导致实际已写入的报告丢图。进程在上传或保存中被强制终止，仍可能产生未被报告引用的长期附件；这些不属于识别临时图，不能用目录生命周期盲删，后续需按报告引用巡检后清理。
- 本次不删除已有食物或包装的历史资料图，不自动回溯压缩或改写已有记录。
