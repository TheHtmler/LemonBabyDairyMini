# 同图营养识别模型对比

原本地工具：`scripts/compare-nutrition-models.js`（临时排障脚本，2026-10-25 已按用户要求移除）。已在用户提供真实图片、本地配置并确认开启免费额度用完即停后，完成 Plus、Flash 各3次真实调用。下方操作说明仅为历史记录，不作为当前执行步骤，实测结果见文末。

后续另用6张包装、实物与翻拍图片完成36次调用，含标签数值核对与身份未知场景分析，见 [六图测评报告](2026-10-22-nutrition-six-image-comparison.md)。不同批次的图片大小不同，不混合推断手机端到端耗时。

## 对比口径

- 固定比较 `qwen3.7-plus` 与 `qwen3.7-flash`，默认3轮，共6次请求；奇数轮先Plus，偶数轮先Flash，串行执行。
- 直接复用生产 `modelClient.js` 的 `callRecognitionModel`、`post`，包括现有提示词、非流式JSON模式、1500输出词元上限、思考模式配置以及解析和归一化。无需修改生产接口。
- 同一次运行固定图片字节、顺序、识别模式、用途、分类目录、端点和密钥，逐次校验剔除模型名后的请求体指纹。仅模型名不同；单次使用生产25秒期限，不自动重试，也不启用备用模型。
- 工具直接访问模型接口，不调用小程序云函数，不执行账号鉴权、额度扣减、参考查询、数据库保存或界面展示。因此这里的总时长不是手机从拍照到完整展示的端到端时长。
- 已有备用模型仅在免费额度耗尽时触发；本工具不复用该切换策略，也不改变线上默认模型或部署。
- 正式对比可能产生费用。模型在某地域可调用，不代表该账号有免费额度；工具逐个使用生产`requireAiPolicy({ scene: 'scan' })`核查两个模型，要求配置中已有经人工核实的`AI_FREE_ONLY_VERIFIED=true`且白名单已包含两模型。缺项则在任何模型请求前失败，不自动设置标记或扩充白名单。

## 必须取得的真实材料

1. 同一次识别实际提交的1至3张JPEG或PNG，每张不超过3MB。最好使用手机裁切、压缩后的同一份输入；若只有原始照片，应如实说明与手机输入不同。不得用图标、占位图或生成图片代替真实营养样本。
2. 该次实际 `mode`、`purpose` 和 `categoryCatalog`。首页自动识别预览通常为 `auto`、`preview`；不要将其他流程的模式直接套入。
3. 可供人工核对的食品身份、营养表基准、原始数字与单位；实物照片估算应注明可接受参考和无法从图片判定的内容。
4. 相同模型服务端点及具备两模型调用权限的密钥。只从环境变量或明确指定的本地环境文件读取，不放入材料JSON、命令行参数或提交到仓库。

2026-10-22准备工具时，代码索引未发现JPG/JPEG/PNG营养图片、`.env`文件或既有同图模型对比脚本；当前执行进程也未设置 `DASHSCOPE_API_KEY`、`BAILIAN_BASE_URL`。该结论仅覆盖代码索引与当前进程，不代表用户电脑其他位置没有材料或凭证。

## 材料描述文件

将以下内容保存在用户自己的本地目录，图片路径相对该JSON所在目录解析；也可使用绝对路径。例子中的路径仅说明格式，必须替换成真实照片。

```json
{
  "images": ["营养表.jpg", "包装正面.jpg"],
  "mode": "auto",
  "purpose": "preview",
  "categoryCatalog": [],
  "expected": {
    "说明": "按真实照片记录人工期望；未知内容保持未知，不将估算当标签读数"
  }
}
```

`categoryCatalog`必须显式提供；空数组代表本次输入确实没有分类目录，并不自动等同当前宝宝的生产目录。`expected`仅供人工对照，不发送给模型，不自动判定识别准确率。材料描述上限256 KiB。

## 先做无请求校验

```bash
node "scripts/compare-nutrition-models.js" --fixture "/绝对路径/材料.json" --dry-run
```

`--dry-run`检查图片真实格式、大小、分类目录及生产请求构造，并确认两个模型除名称外的请求体完全相同；使用截获请求的本地函数在网络调用前停止，不生成虚假的模型结果，不访问模型，也不创建结果目录。无密钥时可使用仅供构造检查的内存占位配置；这不代表真实接口或模型权限已验证。

## 正式运行

可在现有进程提供 `DASHSCOPE_API_KEY`、`BAILIAN_BASE_URL`及项目已有的免费模型策略，或通过 `--env-file`指定本地配置文件。不要将密钥粘贴到聊天；提供本地文件路径即可。已有进程环境变量优先于文件。配置文件只读取这两个凭证键和`AI_FREE_ONLY_VERIFIED`、`AI_FREE_MODEL_ALLOWLIST`，支持普通赋值、单引号或JSON双引号字符串，不执行Shell表达式。

```bash
node "scripts/compare-nutrition-models.js" \
  --fixture "/绝对路径/材料.json" \
  --env-file "/绝对路径/本地配置.env" \
  --rounds 3 \
  --out "/绝对路径/本次对比结果"
```

`--rounds`允许1至20轮。`--out`必须不存在或为空目录，防止覆盖旧结果；不指定时，在系统临时目录创建独立目录。结果文件使用当前用户可读写权限，每次请求后保存当前进度。按Ctrl+C后等待当前请求返回或到期，保留已取得结果，不再开始下一次请求。

## 如何看结果

- `results.json`：每次的模型、轮次、次序、总耗时、模型与HTTP计时、输入输出及可用的缓存词元、结束原因、成功失败、原始回答文本、生产解析后的结果、材料哈希与人工期望。
- `summary.md`：脱敏的逐次耗时和词元表，以及人工质量核对表。该表中的“待人工核对”必须依据真实图片填写，不能当作自动通过。
- 终端不输出密钥、图片路径、图片Base64、接口地址、原始回答或食品名称；仅输出材料数量、配置是否存在、调用状态、耗时及本地结果目录。底层异常原文不会回显。
- 结果JSON有意保留图片识别文本与人工期望，供质量对照；不能视为可直接公开的脱敏材料。文件不含原始图片、Base64、接口地址或密钥，工具不自动上传结果。
- 成功表示生产JSON解析和归一化通过，不表示营养数值已经核实。失败也必须纳入比较，不能只展示最快的成功请求。
- 质量至少核对：商品身份和段数、普通食品/奶粉/实物类型、每份与每100克、干粉/冲调液、数字与单位、NRV列误读、微量/缺失/真实零、证据原文、估算来源及人工改正率。
- 同一批样本配对比较成功率、实际改正项、总时长与API时长。小样本P50/P95只是本次描述，不能代表稳定线上水平；缓存命中、时段和服务负载可能影响先后次序的公平性。

退出码：全部请求解析成功为0；参数、材料、配置、文件错误或任何一次模型失败为1；中断为130。未获真实调用权限、材料或凭证时停留在dry-run，不报告模型速度胜负。
