# 拍照识别分类入口调整

日期：2026-10-19。

后续调整：用户提供直接取景的参考界面后，入口已在 2026-10-20 改为相机取景页，详见 [相机取景页调整记录](2026-10-20-camera-viewfinder.md)。本文保留上一版的实现及当时验证记录。

## 交互与实现

- 入口改为“奶粉 / 食物”两个 Tab，默认奶粉；支持通过 `kind=food` 预选食物。
- 移除进入页面和返回页面时自动弹相机的行为。先选择类别，再点击“拍照识别”或“从相册选择”。
- 拍照继续调用原生 `wx.chooseImage`，限定 `sourceType: ['camera']`、单张；相册限定 `['album']`、最多三张。保留原有压缩和大小校验。
- 奶粉使用 `powder_label`；食物使用 `auto` 区分包装标签与实物。食物入口得到奶粉结果时阻断继续保存，要求明确纠正类型，不自动改为奶粉资料。
- 会话保存初始识别模式和类别，补图及重新识别沿用它们；主动纠正类型后使用新的明确类型。
- 页面移除重复拍摄说明卡片；结果页类型纠正选项默认收起，无法确定或类别不符时展开。
- 保留原有保存恢复、所属宝宝校验、保存后查看及返回搜索流程。此次仅修改小程序页面和组件，不需要新增云端接口或改动数据结构。

- `npm run check:nutrition` 通过：公共模块与部署副本一致，独立加载通过。
- `git diff --check` 通过；两份修改的 WXML 标签闭合检查通过。
- 使用实际页面及组件方法进行离线操作演练：首次进入不弹相机；奶粉拍照参数正确；食物相册参数正确；选图中不能切类别；取消返回解除占用并保留类别；再次显示不重开相机；待恢复保存时不能发起新识别。
- 使用实际组件方法确认奶粉补图和重试仍为 `powder_label`；食物补图仍为 `auto`；主动选择食物实物后为 `food_object`。
- 使用实际工作流和本地回包演练奶粉、食物包装、食物实物，均进入对应预览；食物入口识别到奶粉时停在类型确认，不查询参考或进入保存。
- 使用原有选图工具确认原生相机／相册来源、张数与取消信号传递。
- 将修改后的模板和样式转换为本地浏览器预览，核对 320px 内容宽度下两个 Tab 的提示、主次按钮及换行。浏览器预览不调用相机或云服务，不代替微信渲染验收。
