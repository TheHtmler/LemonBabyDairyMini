# 搜索链路诊断与复制日志

日期：2026-10-29。分支：`codex/search-data-queries`。

当前状态：用户在提交推送前要求清理调试。本文保留临时排查过程；下面描述的复制入口、意图快照、阶段日志、版本日志和耗时打点已全部移除，相关诊断模块及生成副本也已删除。最终版本为 `20261029-search-cleanup`，查询修复继续保留。

## 范围

用户反馈“每100克蛋白质低于5克的我的食物”仍没有结果，要求先补齐诊断信息和复制入口。本轮不修改查询语义或筛选规则，不据示例猜测线上故障原因。

## 实现

- 搜索结果区顶部增加“复制诊断日志”，查询中、正常结果、空结果、错误与能力加载失败时均可使用。点击后仅写入剪贴板，不自动上传或发送。
- 客户端记录实际提交的问题、请求编号、请求模式、版本、能力状态、耗时、响应状态、错误及云调用编号。旧云函数没有详细诊断时仍可复制客户端信息，并提示检查版本与发布状态。
- 服务端按同一诊断编号记录模型请求、意图快照、校验失败、纠错、缓存复用、最终查询条件、有效日期、候选数量、返回数量和阶段耗时；成功、失败和响应缓存分支都保留诊断信息。
- 每个阶段即时输出 `[search-stage]`，即使云调用中途被平台终止，也能用客户端请求编号查询已经执行的阶段。
- 资料读取记录具体来源、集合名、集合是否存在、扫描数量、无效资料数量、候选数量；筛选记录匹配、不匹配、缺少比较依据及分页返回数量。因此可以区分来源错误、私有资料未读到、条件不匹配和数据缺少依据。
- 诊断快照按字段白名单生成，只保留意图所需的名称、指标、来源、日期、单位和条件，不复制账号编号、宝宝编号、实体编号、会话令牌、分页令牌、密钥或完整资料。复制原始问题是为了排查本次用户主动发起的查询。
- 日志仅暂存在当前页面，请求过期或上下文切换时不会覆盖新请求；更换账号或宝宝后不能复制旧上下文日志。每次服务端请求最多记录48个阶段，多余数量单独标记。
- 构建版本更新为 `20261029-search-diagnostics`，协议版本不变。
