# 报告识别云函数调用失败诊断

## 已确认的问题

用户已重建函数、重新上传并配置环境变量，但前端显示「调用识别服务失败，请检查云函数是否已部署」。检查发现该提示来自前端对所有 `cloud.callFunction:fail` 的统一兜底，并不能证明函数不存在。

此前逻辑还把包含 `-501000` 的文本一律判断为未部署，以及把任何包含 `502` 的文本当作OCR网关失败；数字片段不足以确定实际平台错误类别。

当前小程序固定调用环境为 `prod-7g5lap9xcf106dbf`，函数名为 `recognizeReportCustom`。本地没有读取云端实际部署详情，仍需本次SDK原始错误和对应云端日志，才能确认是环境、权限、版本、依赖、初始化或执行失败。

## 修改

- 新增报告专用的云调用错误分类，按固定平台错误类别区分函数未找到、版本未找到、调用权限、数据库权限、环境、函数状态、超时、内存及通用执行失败。
- 移除以通用数字片段判断未部署或网关失败的规则。未知函数调用错误提示查看运行日志，保留合法数字错误码，不再指导反复部署。
- 权限预检与正式识别调用失败时记录 `[report-cloud-call-failed]`，包含阶段、固定函数名、调用环境、合法数字错误码、固定平台错误类别、请求编号及固定失败原因。
- 不输出底层错误原文、调用参数、报告内容、文件标识或密钥；不改变权限策略、模型配置、识别值和云端运行环境。
- 服务端已经返回的业务错误提示及免费额度提示保持优先；单独的数字错误码不能把图片上传失败误归类为函数调用失败。

## 验证及待确认

按用户规则，仅执行JS语法、静态依赖、共享模块一致性与差异空白检查；不编写或执行单元测试、不进行界面验收或真实模型调用，也不部署或修改云端资源。

尚未确认本次调用失败的云端根因，等待用户提供SDK的 `errCode`、`errMsg` 和同一时刻的第一条云端ERROR。若权限预检就失败，可能尚未进入取字阶段，不能据此修改OCR模型或再次重建函数。

官方类别依据：[CloudBase错误码](https://docs.cloudbase.net/error-code/basic)、[依赖缺失排查](https://cloud.tencent.com/document/faq/583/9180)。
