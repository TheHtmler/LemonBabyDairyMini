# 搜索语义与餐次结果修正

日期：2026-10-29。分支：`codex/search-data-queries`。

后续调整：本记录中的句式优先解析已移除，当前转换链路见 `2026-10-29-search-model-first.md`；真实测量规则、餐次结果和详情能力继续保留。

## 问题与处理

- 旧明确语法未完整识别“上一次”“是哪一天”，且仅在模型不可用时降级使用；来源词在营养条件句尾时也未被消费。因此快捷项之外的同义表达仍依赖模型理解，不能只靠增加快捷文案解决。
- 对完整可验证的营养筛选、最近真实测量优先编译已有查询协议；其余自然问句继续交给模型，不静默丢掉未识别条件、否定或逻辑关系。
- “上一次体重变化是什么时候”与“上次主动记录的体重是哪一天”查询全部历史中的最近真实测量，返回测量日期、数值和原记录定位；继续排除自动沿用值。询问变化量时不擅自替换成最近体重值。
- 营养筛选识别句首、句中、句尾的系统／我的／个人来源，保留比较符、单位、基准和全部 AND 条件。仅在明确“没100克”这类计量语境中把“没”容错为“每”；普通否定不变。
- 饮食明细按日期、来源及现有 `mealBatchId` 分组后分页。没有餐次编号的旧记录各自保留，不按餐名或时间猜测合并。筛选命中餐内食物时，结果仍保留整餐上下文并说明筛选针对餐内单项；明确按食物种类去重的查询继续返回食物。
- 综合搜索的饮食记录分组同步使用餐次结果。餐次结果展示餐名、日期时间、食物摘要及数量；普通餐次打开已有餐次页面，没有编号的新记录通过记录编号打开，旧版餐次使用现有预览展示完整条目、数量及备注。
- 账号、宝宝和数据版本变化后禁止打开旧结果。餐次查询使用新的计划标记，旧食物级分页游标必须重新搜索，避免跨版本混入重复结果。
- 构建版本更新为 `20261029-search-semantics`，不改变查询协议版本。

## 代码层面验证

- `npm run build:search`、`npm run check:search`、所改 JavaScript 的语法检查和 `git diff --check` 通过。
- 直接调用已有后端函数进行离线诊断：上一次真实测量可来自 30 天之前；排除较新的沿用值；系统、我的、句首来源、不同计量基准及两条同时满足条件均保留；OR、额外否定、未支持的变化量问句不被明确解析器截断执行。
- 餐次诊断：4 条食物记录归为 3 餐；命中米饭的一餐仍包含青菜；21 餐按 20＋1 分页，合计 21 个独立结果，无跨页重复。
- 模板仅做静态解析和事件绑定检查，未加载或执行页面控制器。未新增或修改单元测试，未进行界面、浏览器或模拟交互验收，未启动服务，未访问真实模型或云数据库，未提交、推送或部署。

线上效果仍需同步发布搜索云函数和小程序；私有食物库没有满足条件的数据时，仍应返回空态，不改查系统库代替。
