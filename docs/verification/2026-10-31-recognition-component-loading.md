# 手机预览版识别组件加载失败

日期：2026-10-31。分支：`codex/ai-model-admin-config`。

## 真实故障证据

用户在刚扫码的手机预览版看到“识别界面尚未加载，请返回后重新进入”。随后提供的 vConsole 截图明确显示：

```text
module 'pkg-milk/components/nutrition-recognition/lib/core/evidenceValidation.js' is not defined
require args is './evidenceValidation'
```

调用链为识别组件入口 → 公共 `index.js` → `normalize.js` → `evidenceValidation.js`。这证明该次预览运行时未注册证据校验模块，导致组件入口加载中断，页面 `selectComponent('#scanner')` 返回空。不是仅凭兜底提示推断加载慢，也不能通过云函数日志诊断这一前端模块错误。

第二张截图存在 `removeTextView:fail` 和 worker 未处理拒绝；没有足够信息判断它与模块错误的因果关系，本轮不据此修改相机或原生视图流程。

## 代码处理

- 本地源文件与所有生成副本均存在且一致，`normalize.js` 的引用路径与大小写正确，项目未显式排除该文件。
- 证据校验此前仅被 `normalize.js` 间接引用；公共入口直接引用其他核心模块，却未显式纳入 `evidenceValidation`。本轮在共享源码入口增加顶层静态引用，并合并其三个校验导出，使其直接进入组件引用的公共模块入口。
- 该处理针对截图中的模块注册故障路径；尚未检查用户手机上的实际编译包，不能把公共入口遗漏直接等同于已经证明的微信编译器内部缺陷。
- 已运行 `npm run build:nutrition`，将同一入口修改同步到小程序与三个营养云函数的公共模块副本。保持标签证据校验、估算门槛、懒加载与未使用文件过滤配置，保留其他未提交改动。
- 本次前端加载修正需要重新编译并生成新的预览二维码；无需为这一错误重新部署云函数。此前番茄制备状态与模型提示的修正仍按其原有发布范围处理。
