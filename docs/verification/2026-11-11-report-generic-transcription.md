# 报告通用取字与后续分类分离

日期：2026-11-11

## 用户纠正与当前状态

用户已确认全零出现在识别结果预览页，并明确要求：图片取字能力不应依赖报告类型，类型只用于识别完成后的数据分类，不应编写指标专属规则干预取字或原值。

本次完成上述职责边界的本地改造。它修正了此前混合职责的实现，但没有取得当次全零的原始模型响应，不能据此宣称全零的实际根因已定位或真实准确率已改善。

## 当前链路

所有已支持报告统一执行：逐图完整原表转录 → 程序固定原行编号 → 模型按表单配置分类 → 校验原行引用与单位 → 汇总冲突并显示原值。

- `buildReportOcrRequest`和原行转录/合并函数不接收报告类型。第一阶段提示词完全相同，没有目标字段列表、指标名称、报告类型或某类报告的选行规则。
- 不再仅转录某些氨基酸、肉碱或其他固定指标；不再按血串联与尿串联切换取字协议，所有支持类型采用相同两阶段调用路径。
- 每张图片最多300原行，最多6张，共1800原行上限；这是通用资源限制，不是业务筛选。最多4个转录并发，保留现有超时、额度及失败后在途用量结算。
- 归属阶段只接收原行编号、原名、原单位及现有表单字段配置。它不接收检测值或参考范围，也不能返回新检验数值。
- 删除识别链路中的临床指标特判、别名白名单、名称正则纠号、血报告专属冲突合并与旧直接生成目标值分支。类型只用于取得最终表单配置及结果归属，整体结果缓存仍绑定类型，避免不同分类结果混用。
- 程序只校验通用协议：字段类型、引用存在、目标有效、单个来源不可多目标、配置单位是否一致、不同原值与范围冲突；不根据某指标名称或参考范围猜结果。
- 不能辨认填空，空值不自动补0；确实转录到0时保留真实零，不能为隐藏故障而把所有零都过滤。阶段数量诊断继续保留，不记录具体检验值或患者原文。

## 数值与范围边界

- 转录原值独立保存在`rawValue`，预览展示原字符串。通用数学写法如`1.2×10^3`和`1.2×10³`可规范为`1.2e3`供填写与精确数值读取，不改动转录原表。
- 云端与前端共用`reportReferenceRange.js`，要求完整识别范围；指数里的负号不能被截成范围端点，`<1e-3`不能截成上限1。
- 单边上限没有原下限时留空，去掉旧范围解析擅自补下限0的行为。这是已确认的范围默认值问题，不把它当作用户检测值全零的证据。
- 单位缺失或不兼容的候选与可交付来源分开保留，不因结果相同就合并后抹去或传播阻断状态。
