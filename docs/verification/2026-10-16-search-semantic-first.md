# 自然问句模型优先与请求语修正

日期：2026-10-16。状态：本地实现与离线验收完成；未调用真实模型、访问生产或启动微信工具，未部署。

## 已确认的现象

用户原句从“最近的天然蛋白摄入系数”改为“查一下最近的天然蛋白摄入系数”后，页面提示不支持“或”和嵌套条件。原句没有这些逻辑，不能把该提示当成用户输入有问题。

修复前直接调用本地代码：

- 旧 `searchMetrics.parseMetricQuery` 能识别原句，带“查一下”时返回未识别；旧模型协议没有系数查询能力。
- 当前 V2 的这两句实际生成相同的 `metrics.series / latest` 计划，服务端合成场景均返回同一日期及数值。
- V2 对“查下”“能帮我……吗”等请求语仍有差异，且主要顺序仍是规则优先、模型兜底。
- 用户给出的旧提示文字不在当前搜索页代码中。这支持旧链路可能仍在运行的判断，但没有读取用户实际请求或生产版本，不能断言部署状态。

## 本次修改

1. 自然问句原样交给模型理解，模型输出对象、指标、时间、操作与条件；前置规则不再决定该问句是否需要模型。
2. 完整真实名称及可验证简称保留直查；手动控件、已确认上下文和翻页不重复调用模型。
3. 模型因配置、额度、网络或格式错误不可用时，仅对能完整确认的明确语法降级；资料对象仍须来自真实授权数据。响应注明 `explicit_fallback`、原因与降级依据，复杂问句不冒充理解成功。
4. `queryText.normalizeSearchRequest` 共用句首请求语、句尾语气词处理，供降级解析和旧指标工具使用。日期、否定、比较、数值及单位保留；模型收到的是原句。
5. 模型对没有逻辑标记的单一问题错误输出 `unsupported_logic` 时，按既有总预算最多修复一次；真实 OR 条件仍拒绝执行，不改为 AND。请求租约、权限或语义冲突不能被降级绕过。
6. 构建标识更新为 `20261016-semantic-first`。页面控制台 `[search-version]` 同时记录客户端和服务端构建，服务端 `[search-v2]` 记录路由、客户端版本及诊断 ID，不记录原句和个人数据。

## 用户预览与发布边界

- 需同步完整 `searchManager` 与小程序包。只刷新页面、只上传某个文件或保留旧编译包，不能保证运行本次实现。
- 微信开发者工具由用户自行验证。`[search-version]` 中客户端及服务端预期均为 `20261016-semantic-first`；如继续出现旧提示，可据该日志区分实际运行版本。
- 模型仍受既有免费模型白名单、配置和每日额度约束，未新增付费兜底或放宽限额。自然问句会使用原有搜索额度，明确名称直查不使用模型。
- 未核验真实模型在用户当前环境中的输出；需按原语料单独验证，不宣称泛化效果已经达到目标。
