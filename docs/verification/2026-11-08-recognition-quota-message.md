# 识别模型额度耗尽提示统一

日期：2026-11-08

用户要求报告识别、食物实物识别、包装食品识别统一显示：

> 识别失败，模型额度用完，请给管理员发送反馈申请

## 改动

- 新增纯共享模块 `packages/ai-access-core/recognitionErrors.js`，统一文案与额度错误码识别；通过现有构建流程同步到独立云函数及小程序。
- 报告与营养识别模型客户端将 `insufficient_quota`、`AllocationQuota.FreeTierOnly` 识别为额度耗尽，保留原服务错误码，继续沿用既有备用模型切换机制。普通403权限错误不误判为额度耗尽。
- 报告、营养场景所有已启用且已验证的模型均被额度阻断时，权限预检同样返回统一提示；没有配置可用模型、服务关闭、密钥缺失和个人每日次数上限保持各自含义。
- 前端保留额度错误码；食物和食品共用的预览组件不再将额度提示覆盖为“未识别成功，请重拍或重试”。
- 报告结果页在额度耗尽时移除“点击失败图片重试”附加提示，并将失败图片角标改为“识别失败”。
- 后续按用户要求，将“发送反馈”改为带下划线的可点击链接，使用共用组件直接打开 `/pkg-misc/feedback/index`。该页默认展示发送反馈表单，不跳转到历史反馈列表，也不自动提交反馈。
- 链接覆盖报告结果页、食物/食品识别的预览错误与填写错误提示，以及拍照入口的模型额度不可用提示；完整文案继续从同一份共享常量拆分，避免链接前后文字漂移。

## 验证范围

- 执行共享模块构建、构建一致性检查、小程序静态依赖检查、相关 JavaScript 语法检查及差异空白检查。
- 遵守默认单元测试偏好，本次不新增或修改单元测试；未执行界面、浏览器或模拟页面验收。
- 遵守用户暂停付费验证的选择，未调用真实模型，未发送图片或写入业务数据。
- 本地改动未部署、提交或推送。生效需要更新小程序，并完整部署 `recognizeReportCustom` 与 `recognizeNutritionLabel`，包含各自的共享模块。
