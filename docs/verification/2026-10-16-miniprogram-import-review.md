## 审查发现和修正

1. **检查范围遗漏首页和组件。** 原脚本默认只遍历搜索页，且只确认相对 JS 文件存在；这不是完整的小程序依赖验收。现从 `app.json` 遍历全部页面、分包、组件，并检查 JS、模板、样式的静态引用、文件大小写、包边界与打包排除规则。仍支持指定单个 JS 入口作定向检查。
2. **构建无条件重写文件。** 原脚本即使内容没变也直接覆盖全部生成文件，增加文件监听事件且存在读到半写入文件的窗口。现先解析全部生成内容、确认依赖、按依赖顺序处理，只对变化内容作同目录原子替换；构建和只读检查均执行全入口检查。单文件原子替换不等于跨文件事务，不声称能控制微信编译器何时重建。
3. **基础模块加载整个搜索入口。** 喂奶工具、系统食物、系统奶粉索引仅需 `indexNutrientStates`，却引用搜索总入口。已直接引用 `search-core/nutrition`，保持同一个函数实现，减少无关启动依赖；同步了云函数内的喂奶工具副本。
4. **文本正则不能可靠识别 JS 引用。** 独立复核指出注释/字符串误报和动态路径漏报。新增开发依赖 `acorn@8.15.0`，用语法树解析静态 `require` 和导入；动态路径、未覆盖的异步模块引用和 npm 引用明确失败，不静默跳过。页面 JSON 可选，组件 JSON 必须声明 `component: true`。

没有复制营养算法，没有将关键模块缺失捕获成假数据，没有修改微信项目配置、AppID、基础库版本或优化开关。业务 SDK 声明不变；本地安装的 `wx-server-sdk@3.0.1` 和 `@cloudbase/node-sdk@3.18.1` 保持任务开始时版本。
