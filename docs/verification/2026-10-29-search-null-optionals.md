# 搜索意图可选空值修复

日期：2026-10-29。分支：`codex/search-data-queries`。

提交前状态：按用户要求移除临时诊断快照、复制入口和各阶段调试打点，保留本文的空值校验修复及排查证据。最终构建版本为 `20261029-search-cleanup`。

## 证据与根因

- 用户提供的实际查询为“每100克蛋白质低于5克的系统食物”。客户端和服务端均为 `20261029-search-diagnostics`，请求在 `understand` 阶段失败，没有进入资料读取。
- 第二次模型输出已经包含 `catalog.search / food / system` 和完整的蛋白质 `< 5 g / 100 g` 条件，但同时输出了 `basisQuantity: null`、`featureId: null` 等不适用的可选字段。
- 原校验将顶层 `basisQuantity: null` 当作非法数字；继续执行时，`featureId: null` 也会被当作非法功能编号。模型重试无法解决这类协议空值处理不一致。
- 本地直接校验日志中的意图，可以复现“搜索条件无效”；仅移除可选空值后，同一意图可以通过结构和执行约束校验，来源、比较符、数值及筛选基准均未改变。
- 第一次“查询指标与操作不匹配”的报错无法仅凭原快照完整重现：旧日志会丢弃数组内的对象，不能据此推断具体原始类型。本轮补充类型标记，供后续诊断使用。

## 变更

- 共享校验在确认字段白名单后，将可选字段的显式 `null` 统一视为未提供，复用已有默认值；覆盖意图、日期和筛选项，不改变实际查询规则。
- 必填字段仍严格校验，比较数值和筛选基准缺失不会被补造；未知字段即使为 `null` 也会拒绝。
- `measure` 和 `measures` 增加明确的类型反馈，并说明资料数值比较应写入 `filters`，供模型纠错使用。
- 模型指令明确可选空值和指标字段类型；诊断快照将原先丢弃的对象或数组记录为类型标记，不复制其中的私有内容。
- 构建版本更新为 `20261029-search-null-optionals`。继续使用现有分支，保留所有原有工作区改动。

## 验证与边界

- 使用用户日志中的第二次意图直接校验，`system`、`mine`、`all` 三种来源均通过，原始蛋白质条件完整保留。
- 使用本地资料读取替身调用实际的计划编译、资料归一化和筛选实现：系统及私有来源各读取2条并匹配1条，全部来源读取4条并匹配2条；高蛋白资料均被排除。
- 核对功能入口、最近真实体重记录、尿布筛选、排除配料和日期条件的可选空值处理；未知字段、必填操作为空、比较值为空、比较基准为空、对象形式指标、非法功能编号和零基准仍被拒绝。
- 新类型标记只显示类型，不复制用于诊断的对象内部私有值。
- `npm run build:search`、`npm run check:search`、改动的 JavaScript 语法检查及 `git diff --check` 通过。
- 未新增或修改项目单元测试；未执行页面控制器或界面验收，未访问真实模型或云数据库，未启动服务，未提交、推送或部署。

更新小程序与相关搜索云函数后，需以实际数据的搜索结果确认线上行为；本地替身诊断不代表真实模型在所有自然语言问法上的准确率。
