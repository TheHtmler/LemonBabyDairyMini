# 搜索来源、日期、药物与摄入系数调整

日期：2026-10-15。仅完成本地源码、离线调用与编译检查。按用户要求未启动微信开发者工具，未修改 AppID、基础库配置或生产环境。

## 实现决策与文件

1. 搜索来源使用现有食物记录组件的标签样式：绿色“我的”、蓝色“系统”，在结果名称旁和详情标题显示；来源筛选文案同步缩短。修改 `miniprogram/pkg-milk/search/index.js`、`index.wxml`、`index.wxss`。
2. 普通饮食记录默认继续采用含当天的滚动近 30 天，明确显示起止日期。记录范围直接提供近 7 天、近 30 天、全部历史、自定义；切换立即查询并保留关键词、营养条件和搜索类型，自定义须明确应用完整日期。资料搜索本身没有 30 天限制。
3. `packages/search-core` 增加 `medication` 资料范围；`cloudfunctions/searchManager/repository.js` 接入当前宝宝的 `medications` 集合，复用既有鉴权、分页、详情访问检查。药物展示已记录的剂量、频率、浓度和备注，支持打开用药管理，不展示食物能量，也不参与营养筛选。`searchFeatureCatalog.js` 与服务端能力列表增加用药管理入口。饮食记录范围仍只包含食物、奶粉、食谱，没有把用药记录混入饮食。
4. `miniprogram/utils/searchMetrics.js` 确定性识别“最近的天然蛋白摄入系数”，同时支持现有特殊蛋白、总蛋白、热量摄入系数及明确的今天/昨天/上周/近 N 天等范围。没有明确范围的“最近”指最近一次有饮食记录的日期；有范围时显示最近 7 个记录日期，并标明展示范围。目标、医嘱、阈值比较、平均值等不被这个入口误解析。
5. `searchManager/metricDates.js` 只读定位日期；`index.js` 在宝宝权限和搜索开关检查后开放 `metricDates` 操作。客户端调用既有 `getDailyRecordV2(..., { readOnly: true })` 临时构建当日汇总，并复用 `reportWorkbench.buildDailyNutritionMetricFromSummary` 计算。只读分支不创建成长记录、不写回汇总或业务缓存；来源明确失败时不返回部分统计。缺少体重不显示虚假零值，实际系数不使用目标系数。
6. 系数结果显示日期、单位、计算体重和当日记录入口；账号、宝宝、查询轮次变化后丢弃迟到结果。

共享搜索模块已通过 `npm run build:search` 同步，`npm run check:search` 验证源与构建产物一致。

## 模块引用纠正

用户实际运行报告 `module 'utils/search-core.js' is not defined`。根因是 `searchMetrics.js` 使用 `require('./search-core')` 目录简写：此前 Node 验收自动回退到 `index.js`，掩盖了微信模块加载器的文件路径要求；模板编译也不会执行 JavaScript 引用链。现改为只引用所需的实际文件 `./search-core/period`。

新增静态校验脚本 `scripts/check-miniprogram-imports.js`，递归检查入口及静态相对 `require` 的实际文件存在性，不采用 Node 目录回退，并包含函数内部延迟引用。提供 `npm run check:miniprogram-imports`，同时接入原有 `npm run check:search`，后者会在模块引用不合法时失败。脚本只核对路径，不等价于完整微信分包、打包规则或真机运行验收。
