# 包装营养表提取与回填修复

日期：2026-10-20。用户补充：拍的是包装上的营养成分表，而非没有标签的食物实物。

## 问题定位与边界

上一轮将重点放在无参考的实物照片如何显式估算，未覆盖用户此次描述的标签读数丢失问题。包装标签应优先读取并回填图片中的数值，参考库与估算不能代替此步骤。

当前代码流程：

1. 准备会话并上传图片。
2. 调用视觉模型，自动模式先区分食物标签、奶粉标签或实物，同时提取身份、营养数值、单位、表头基准及证据。
3. 服务端归一化单位和数值，保留标签依据；无法确认的字段保留未知。
4. 客户端按当前填写基准换算，自动采用未手动修改的标签字段。
5. 查询营养参考，补充缺项或提供对照；符合条件的普通食物可另行主动申请估算。
6. 用户核对资料后确认保存。

静态代码确认两个可导致标签数值无法回填的断点：

- 模型提示要求返回标签原始单位，但解析器仅接受英文缩写。返回“克、毫克、千焦”等中文单位时，营养数值被改为缺失；表头单位返回“克、毫升”也无法形成有效换算基准。
- 普通食品标签未给出内部 `material` 字段时保留 `unknown`，客户端目标固定为 `food`，导致已有表头数量、单位及营养读数也无法换算。服务端生成的 `patch` 与客户端重新换算结果可能不一致。

尚未取得用户此次照片、模型原始响应或线上会话。用户不确定结果类型，因此不能断言上述某一条就是这次线上实例的唯一原因，也未确认是否发生分类错误。

## 修改内容

- 为营养单位和表头单位统一处理中文、英文全称、大小写、全角及空白写法，沿用原有单位换算；不将含义不明确的“卡”直接等同于千卡。
- 已确定为普通食品标签时，省略物料类别按 `food` 处理；奶粉干粉、冲调液仍需明确区分，不推断缺失重量或体积。
- 自动识别提示明确优先提取可见营养成分表，不因包装上的食物图案或生熟状态不明转成实物模式；同时强调含量列、NRV 列及表头基准的区别。
- 保留已提取但尚未回填的标签数值，在预览和核对表单中标为“标签提取值／尚未回填”；缺少表头、单位不兼容或奶粉换算依据不足时显示具体原因。
- 尚不能换算的标签读数只作展示，不自动保存为当前填写基准，也不提示用估算掩盖该问题。
