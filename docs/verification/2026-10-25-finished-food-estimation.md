# 普通成品食物营养缺失排查

用户反馈“青苹果慕斯蛋糕”能识别名称，营养均显示未识别；已明确照片为蛋糕实物，不含营养成分表。本轮依据代码查出规则缺口，未取得该次云端原始结果，不将规则检查表述为真实图片复测。

## 原因与修复

- 估算资格与识别提示词仅允许 `raw/boiled/stir_fried`，普通糕点、甜点及其他明确成品使用的 `other` 被排除；前端估算入口依赖同一资格判断，因此也不会出现。
- 参考匹配将 `other` 与 `unknown` 一起拒绝，即使资料库已有同名、同状态的已核验成品条目，也无法采用。现在只拒绝状态未知或双方制备状态不同，品牌、系列、条码、具体名称和可信别名的匹配规则不变。
- 首轮识别估算与单独估算均支持明确的普通成品，按完整食品的常见做法估算每 100g 营养，不能将名称中的水果等单一配料代替整个食品。提示词要求记录通用配方假设，不声称得到了真实配方。
- 前端确认选项增加“其他制备 / 成品”，同时更新校验与选项映射，避免要求用户将蛋糕错误选为生鲜、水煮或炒制。
- 营养继续逐项标注“AI 估算”，包装标签、奶粉停用、特殊配方、品牌产品、身份确认、缺项、数值范围及保存绑定限制保留。未添加或接入其他营养数据库，也不推断薄荷健康此次显示数值的数据来源。

- 小程序静态依赖检查通过：67 个页面／组件、381 个文件、430 处引用；营养公共模块重新构建并通过部署产物一致性、独立加载、JS 语法及差异格式检查。
- 一次性静态语法树检查确认：旧估算规则排除 `other`，新规则与前端选项一致；参考匹配仅调整制备状态门槛，身份、品牌、条码、可信来源、营养校验与模型请求用量逻辑保持一致。
- 按用户约定未新增或修改单元测试，未执行界面或模拟交互验收，未调用真实模型、线上接口、部署、提交或推送。实际图片分类和生成结果尚未复测。
