# 报告识别运行环境问题与多余部署配置撤销记录

## 已确认的原因

用户确认云端 `recognizeReportCustom` 当前使用 Node.js 16；新引入的 sharp 0.35.5 要求兼容 Node-API v9 的运行时，例如 Node.js >=20.9.0。原有 `package.json.engines` 只声明依赖要求，不会自行改变已经创建的云端函数环境。

## 已撤销的修改

- 删除本轮额外新增的根目录CloudBase CLI配置文件。
- 移除本轮额外新增的单函数CLI部署脚本，恢复项目原来的部署方式。
- 移除错误提示中对这套部署配置的引用。

新增CLI入口不能绕过云平台对运行环境的限制，对用户当前的微信开发者工具部署方式没有必要，因此在用户要求撤销多余修改后移除。该CLI入口从未执行，没有安装CloudBase CLI或修改任何云端资源。

## 保留的修改

- 报告自动分块取字、超限继续细分及分批分类逻辑。
- sharp依赖及其Node.js版本要求。
- 分块组件分别报告运行时过旧、依赖缺失或依赖加载失败，并提供实际Node.js版本；诊断仅包含固定原因和平台版本，不记录底层错误原文、密钥或报告内容。

## 云端仍需处理

Node.js16无法满足当前sharp依赖要求。需在云平台确认现有函数是否能直接调整运行环境；若不能，应按平台支持的迁移方式处理。本次没有执行升级、删除或重建云端函数。

运行环境满足要求后，继续用微信开发者工具的“上传并部署：云端安装依赖”，不要将Mac的原生依赖包当作Linux依赖上传。单独修改业务代码、包版本或发布函数代码版本，不能证明实际Runtime已经升级。

## 验证范围

执行包清单JSON解析、JS语法检查、共享模块静态检查及差异空白检查。未新增或执行单元测试，未调用模型、操作界面、安装全局工具、部署、删除或修改任何云端资源。
