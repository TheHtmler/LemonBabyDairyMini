# 搜索、拍照录库与 AI 设置审查修复

## 范围与约束

落实用户授权的四项审查修复，继续使用 codex/ai-model-admin-config，保留开始前的全部未提交改动。不新增或修改单元测试，不进行界面交互验收或数据库模拟，不启动服务，不部署、不提交、不推送、不调用生产 API。

## 修改与关键决策

1. AI 模型状态：packages/ai-access-core 的模型配置、状态和额度同步统一采用 CloudBase Node SDK 直接文档写法。featureFlagManager 的三个 AI action 使用该 SDK，其他开关仍使用原微信 SDK；syncAiModelQuota 也改用同一接口。两函数声明项目已有的 @cloudbase/node-sdk ^3.16.0 依赖，无需升级项目核心依赖。固定模型状态及运行状态若曾被错误写入 data 层级，读取时通过事务重新核对并修复；不会把成功请求或额度刷新当作清除耗尽标记的依据。本次没有连接云端执行修复。

2. 搜索阈值：意图协议增加 threshold，完整保存待补条件的营养指标、比较符、单位和份量基准；已有条件留在 filters。补数值时仅追加条件，追问文案跟随高于、低于、等于等方向及克、毫升、份基准。格式缺失交由现有模型纠错，不再默认蛋白质低于某值。奶粉先确认干粉或冲调液，再补阈值。能力版本更新为 search-2.2.0；模型缓存规则指纹随指令变化。

3. 自定义单位：foodBasis 共用校验允许最终手填表单采用袋、勺等非空、无控制字符、最多 40 字符的记录单位，份量仍须为有限正数。标签、参考和估算的自动换算范围保持标准单位；自定义单位的最终营养数值按手填记录，保留原始识别证据。绑定与确认保存共用此规则，不更改会话、身份、版本和事务保护。

4. 摄入查询：普通摄入量不再加载成长记录、历史体重和宝宝档案。系数只查询所需日期内的成长记录，复用已读取的喂奶快照，并按需降序查找范围前的一条有效体重。回溯分别处理日期字符串和数据库日期，仍按宝宝、有效状态限定，受现有读取和时间预算约束，并参与查询期间及分页的数据变更核验。无既往成长体重时才回溯喂奶快照，仍无体重时才读取宝宝初始档案；保留原有体重来源优先级。
