# 搜索数据能力扩展：第一批实施记录

日期：2026-10-28。分支：`codex/search-data-queries`。状态：本地实现和代码层面复核完成，尚未提交或发布。

## 已实现

- 成长：体重、身高、头围的真实测量记录、最新值、时间序列、测量均值、最值、期间增量与两段比较。按指标独立处理同日重复记录，排除自动沿用、无效值和未来测量；增量不足两次测量时明确缺依据。
- 护理：睡眠与尿布的明细、次数、合计／日均、逐日序列及比较。睡眠按上海时间裁剪跨日区间，未结束或缺少结束依据不当成完整时长；次数按开始日归属。混合尿布纳入大便或小便查询但不重复计数，未知性状／颜色不当作确定不命中，定性尿量不转毫升。
- 现有记录：补充喂奶、饮水、服药数量的逐日序列；不同单位不强行合并，服药用量趋势需要确定具体药物。资料含量和实际饮食摄入保持区分；不以整瓶混合奶的营养替代某款奶粉的实际营养贡献。
- 名称式输入：新增 `catalog.browse`，按相关资料、食谱和最近记录分组，每组先展示 3 项。组内“查看全部”沿用同一匹配逻辑、冻结日期和服务端游标，每页 20 项；保存返回时保留分组解释快照。无明确日期的相关记录默认近 30 天。
- 歧义：明确属性／实际记录问法直接查询；确实影响数值含义时才补充一次查询方向。实际摄入执行器一次仅支持一个指标，多指标选择实际摄入时明确说明限制，不静默截断。
- 前台：保留简洁搜索页，仅在结果内增加分组标题、查看全部和原始记录入口，补充测量日期与增量起止日期；不增加分类栏、条件标签或高级筛选。缺少原记录的空日期行不可点击。

## 主要工程决策

- 沿用当前能力注册、意图校验、编译、鉴权、预算、来源复核、请求缓存、上下文和签名游标；新业务结果继续使用原 `list/scalar/series/comparison` 类型。
- 分组注册在共享能力表；`browseGroup` 是受白名单限制的解释字段。查看全部只限定同一组，不转换成另一套名称解析，以免展开后漏掉配料或历史命中。
- 只读查询直接通过服务端 reader 取数据，不调用会补写成长记录或汇总的页面服务。`overlapSleep` 负责睡眠区间候选读取，执行器再严格校验。
- 新域定位复用既有“打开对应日期记录”路径，不需要改动客户端记录模型或新增编辑入口。
- 共享源码通过 `build:search` 同步；仅增加纯成长来源工具的云端副本，没有新增依赖或数据库集合。

- `npm run build:search`、`npm run check:search` 通过。静态依赖检查覆盖 67 个页面／组件、381 个文件和 435 处引用；共享源码与部署副本一致。
- 新增与修改的搜索服务端源文件语法检查、搜索页静态表达式与方法引用、31 处模板事件及标签闭合检查通过；没有加载或执行页面控制器。
- 服务端编排在一次性内存数据库中完成 24 次请求复核，使用实际意图校验、计划编译、数据读取、查询执行器、来源复核与上下文／游标代码。覆盖自然体重问法、真实测量增量、非法聚合、跨日睡眠、最新未结束记录、混合尿布与未知筛选、每日饮水、名称分组与展开分页、跨午夜日期冻结、方向澄清、来源失败及宝宝权限。

- 成长与护理执行器分别完成纯服务端边界复核，覆盖沿用源、重复测量、单次增量缺依据、旧时间格式、分页、不同范围缺记录、未知筛选和来源错误。
- 独立只读审查发现的多指标截断及成长统计缺少明细入口均已修复；修复后的拒绝截断、原始记录展开和比较分段展开已纳入上述编排复核。
