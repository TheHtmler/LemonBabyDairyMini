# 报告识别接入千问 OCR 与管理员配置

日期：2026-11-07
分支：`codex/report-ocr-qwen`

## 当前行为

- 管理员“AI 模型配置”增加独立的“报告识别”页签，候选为 `qwen3.5-ocr`，不混入搜索或食物模型名单。
- 报告识别仅调用千问。原自建地址、健康检查、`CUSTOM_OCR_*` 变量、图片转发协议及回退路径已移除；云函数继续使用既有名称 `recognizeReportCustom`，前端调用路径不变。
- 新报告模型默认关闭、未核验；旧配置在读取时补齐报告名单，保持原有搜索与食物模型顺序、开关及版本。管理员确认业务效果并保存后才启用，不自动把百炼侧开通视为业务核验。
- 配置保存和模型调用不依赖额度快照的新旧或是否查询成功。免费额度与保护状态的查询列表增加该模型，调用返回免费耗尽时写入既有阻断状态，不回退其他识别源。
- 报告识别保留用户开放范围，并检查宝宝成员权限、图片路径及格式；调用只能使用管理员选择的模型，不能由客户端覆盖。
- 复用已有计数与请求幂等机制，报告按独立场景计数，默认每用户每日 20 次；错误请求在发出模型调用前不扣次数，同一请求不会重复发起模型调用。
- 使用官方 OpenAI 兼容 Chat 接口，单次模型等待最多 45 秒；不发送该 OCR 接口未声明支持的强制 JSON 模式或思考模式参数。模型结果必须完整结束、通过 JSON 及字段校验才交给原有紧凑预览和确认创建流程。
- 请求只提取指标、结果、单位、参考范围及高低标记，不要求模型补值、解读病情或输出个人身份信息。日志仅记录模型、条目数和固定错误码。
- 云端检查实际格式及大小，不重复缩图。后续质量修正已将两端上限统一为 6 MB，并保留上限内原图、增加同源目标校验，详见 `2026-11-07-report-recognition-quality.md`；真实照片准确率仍需对照验证。

## 发布与启用

本轮只完成本地代码，没有部署、调用真实模型、修改云端配置或写入生产数据。

1. 本地执行 `npm run build:search` 后，完整部署 `recognizeReportCustom`、`featureFlagManager`、`searchManager`、`recognizeNutritionLabel`、`syncAiModelQuota` 五个函数，包含各自的 `lib/ai` 生成目录。它们共享模型配置格式，须同步发布，避免旧管理函数保存时丢失新场景。
2. `recognizeReportCustom` 新增依赖 `@cloudbase/node-sdk`，部署时安装该函数 `package.json` 中的依赖，锁文件已同步；已移除直接依赖 `form-data` 和 `jimp`。
3. 为 `recognizeReportCustom` 单独配置 `DASHSCOPE_API_KEY` 与 `BAILIAN_BASE_URL`。其他云函数中已有同名变量不会自动继承。密钥需属于已开通模型的百炼账号及对应业务空间，只通过云端私有配置填写。
4. `BAILIAN_BASE_URL` 使用官方北京地域地址，形如 `https://<业务空间ID>.cn-beijing.maas.aliyuncs.com/compatible-mode/v1`，保留用户已使用的合法业务空间地址；无需配置模型名环境变量。
5. 报告每日上限优先使用管理员“识别次数配置”中的报告设置；尚未保存时才由 `REPORT_OCR_DAILY_LIMIT` 兜底，整数范围 0–10000，默认 20，0 表示暂停新增报告识别。模型调用超时 45 秒，云函数建议沿用或设置至少 60 秒超时。统一次数配置发布说明见 `2026-11-07-recognition-quota-admin.md`。
6. 重新编译发布小程序。管理员进入“AI 模型配置 → 报告识别”，开启 AI 服务，启用 Qwen3.5 OCR，确认核验提示并保存。用户仍须在既有“报告拍照识别权限”开放范围内。
7. “刷新额度”可查询显示，不是使用前置步骤；免费用完即停继续依赖百炼端对应模型的保护开关。这里不代改百炼保护状态、访问密钥或云端环境变量。
