# 营养零值与每日汇总修复记录

日期：2026-11-06。分支：`codex/nutrition-zero-value-fix`，从 `main` 的 `fc71193` 创建。

## 问题与处理

- 系统食物的历史零值没有字段证据，会被索引标为缺失。旧列表又把缺失显示为零，表单则显示为空。
- 系统食物另存、覆盖副本、普通编辑共用营养写入协调逻辑。用户明确输入的合法数值（包括零）同时保存已知状态，并清除相应旧缺项标记；未编辑的识别数据保留原精度和来源。
- 数据库更新整体替换营养值、状态和缺失映射，防止嵌套合并留下旧状态。宝宝归属、版本条件与并发保护保留。
- 按用户最终确认的规则，食物营养缺失值统一按零显示、保存和计算。逐条累计热量、蛋白、脂肪、碳水、膳纤，不再用一条记录的缺项清空其他食物的贡献。客户端、搜索云函数、独立重建云函数使用同一规则。
- 食物另存与编辑、饮食记录快照、整顿合计和食谱配料合计采用同一零值规则；来源证据留在原始元数据中，不用它覆盖实际计算数值。
- 新摘要带 `nutritionAggregationVersion: 1`。正常单日读取和启用重建的范围查询会识别旧摘要并重建；不通过归一化给旧摘要冒加新版本。
- 数据记录页保留“总热量／总蛋白”，不显示营养缺项提示；系数和供能比例按零值兜底后的合计正常计算。此前新增的完整性提示、缺项拦截和占比占位逻辑已移除。
- 系统食物导入保留原始字段证据：确认零、缺失、微量和阈值不再混为一谈。索引 schema 升至 3，旧缓存的快速读取和回退路径都受版本检查。
- 按用户追加要求移除食物管理表单中的拍照识别入口、组件挂载、回填回调、识别保存分支和专属样式；保留主页拍照识别、手动录入和普通图片上传。
