# 搜索与食物拍照识别精简记录

日期：2026-10-19。

本记录对应第一轮页面与共享模块精简。用户随后确认项目处于开发／测试，可停止兼容旧搜索实现；旧服务端 API 的后续删除及集合处理以[云函数与集合精简记录](2026-10-19-search-cloud-cleanup.md)为准。

## 分析结论

可以精简。当前主要冗余来自搜索升级后遗留的前端解析链路、同一小程序内部的重复打包，以及识别流程中的少量无调用工具和重复状态。识别的主要业务阶段仍有实际用途。

当前有效链路：

- 文字搜索：搜索页 → `searchService.search` → `searchManager/orchestrator` → 意图解析、实体定位、查询计划 → 资料／记录／指标结果。
- 搜索拍照入口：首页或搜索页 → `nutrition-scan` → 共用 `nutrition-recognition` 组件，以自动模式识别，先预览，再确认保存。
- 食物、奶粉表单：同一识别组件使用指定模式，结果经用户采用后回填原表单。
- 识别服务：准备上传 → 图片识别 → 营养参考 → 符合条件时补充估算 → 核对并保存。
- 两条功能链通过资料库衔接；识别保存或恢复成功后使搜索会话失效，后续查询读取更新后的资料。

因此保留搜索和识别各自的职责；无需再复制识别组件，也无需把查询与保存强行合成一个接口。

## 已完成的精简

### 旧搜索链路

- 删除无导入的 `miniprogram/utils/searchMetrics.js`，不再保留前端自行解析系数查询、逐日读取记录并临时计算的旧方案。
- `searchService` 只保留当前页面使用的请求编号、能力查询、统一搜索和预览接口，移除无调用的 `interpret/execute/metricDates` 包装。
- `searchFeatureCatalog` 只负责按服务端许可打开功能入口，删除无调用的本地关键词检索与无消费者的导出。
- 删除共享核心中无调用的 `parseAttributeQuery`、`parseCatalogQuery`、`needsSemanticSearch` 及专用常量；保留仍被使用的日期解析与旧模型结果归一化。
- 合并两层搜索结果格式化，去掉没有视图或业务消费者的 `calorieText/aiAvailable/diagnosticId` 页面字段。诊断编号仍保留在完整响应中。
- 删除搜索编排器的未使用导入。

### 小程序重复打包

- 搜索页从主包分别引用 `capabilities/contracts/period`，移除 `pkg-milk/search/lib/search` 下 13 个重复模块。
- 构建脚本移除该分包生成目标，避免下次构建重新生成。
- `pkg-milk` 为普通分包；主包相同文件原已存在，没有增加主包文件。全入口静态依赖检查确认没有跨分包违规或引用缺失。
- 云函数仍独立携带运行依赖；营养识别的 39 个部署副本继续保留并由构建同步。

### 识别流程

- 删除无调用的 `toComparableBasis` 和 `displayNumber`。
- 删除同一识别草稿分支中第二次相同的过期检查。
- 识别弹窗直接使用公共 `REQUIRED` 必填字段，移除重复常量和无消费者导出。
- 合并编辑营养值时重复的手填标记逻辑。
- 公共源码和生成副本已同步，不手工维护两套实现。

## 本次保留的逻辑及原因

- 服务端旧 `interpret/execute/metricDates` API：既有发布记录明确要求发布窗口兼容旧客户端；仓库无当前调用不能证明已发布客户端不再使用。未确认旧客户端退出前保留这组外部接口。
- `queryService.publicCandidate`：新搜索和预览也在使用，不能随旧执行器一起删。
- 日期确定性解析、搜索权限、分页和会话失效：仍被当前搜索实际调用。
- 自定义日期展开状态：服务端返回的具体日期范围会成为动态选项，不能只按固定选项索引派生，否则应用后会意外收起编辑控件；经独立审查后保留原实现。
- 识别参考查询和可选估算：分别处理可信参考和普通食材缺项，奶粉等不适用通用估算的限制继续保留。
- 图片来源、权限、目标绑定、比较版本、幂等保存、失败恢复：防止串宝宝、过期结果覆盖及重复添加，均有实际消费路径。
- 两个看似重复的入口检查继续保留：`operationId` 正则会隐式转换数字，后续字符串校验仍有必要；`action` 初次校验带默认值转换，后续校验仍负责拒绝空值等异常输入。
